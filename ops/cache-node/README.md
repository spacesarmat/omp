# Узел кэша популярных раздач

Отдельный сервер с TorrServer и небольшим агентом. Он заранее держит начало раздач, которые биллинг счел популярными или которые админ закрепил вручную. Приложение может открыть такой узел как быстрый источник, но только если в биллинге включен переключатель. Пока переключатель выключен, телефоны, телевизоры и Windows-версия работают как раньше.

`ops/vps/deploy.sh` этот каталог не ставит и не перезапускает. Узел живет на своей машине.

## Что нужно до установки

1. Новый образ биллинга с миграцией `007_cache_nodes`. Миграция применяется сама при старте биллинга. Пока образ не выкатили, админки «Кэш» на сервере нет.
2. В админке, вкладка «Кэш»: имя, адрес вида `http://cache.example:8090`, регион, емкость в гигабайтах. Кнопка «Добавить и выдать токен» показывает токен один раз. В базе лежит только его хеш.
3. Переключатель «Включено» оставьте выключенным, пока узел не пройдет проверку. Расчет популярности и выдача источника приложению при выключенном флаге не работают. Heartbeat при этом уже пишется, узел виден в таблице.

Секреты в git не кладутся. Файл `/etc/omp-cache-node/config.env` создается на сервере, права `600`.

## Установка на чистый Ubuntu

Нужны root, исходящий доступ к биллингу и Docker. Скрипт сам поставит `docker.io` и Compose v2, если их нет.

```bash
sudo apt-get update
sudo apt-get install -y git
git clone https://github.com/spacesarmat/omp.git
cd omp/ops/cache-node
sudo ./install.sh
```

Первый запуск остановится и попросит конфиг, контейнеры не поднимет:

```bash
sudo nano /etc/omp-cache-node/config.env
```

Заполните:

- `BILLING_URL` - адрес биллинга, без логина и пароля в ссылке.
- `NODE_TOKEN` - токен из админки.
- `CACHE_PUBLISH` - по умолчанию `127.0.0.1:8090`, снаружи порт закрыт. Для приема зрителей поставьте `0.0.0.0:8090`.

Снова:

```bash
sudo ./install.sh
```

Проверка с самого сервера:

```bash
curl -fsS http://127.0.0.1:8090/health
```

В ответе `ok: true`. `torrserver: true` значит внутренний TorrServer отвечает. В админке у узла статус «онлайн», видны диск и время heartbeat.

## Файрвол

Скрипт файрвола не запускается сам. Он разрешает SSH и TCP-порт из `CACHE_PUBLISH`, затем включает ufw. Остальные входящие закрываются.

```bash
sudo ./firewall.sh
```

Или сразу при установке: `sudo ./install.sh --firewall`.

Не публикуйте порт TorrServer отдельно. Наружу смотрит только агент: `/health`, `/echo` и потоки `/stream` и `/playlist`. Добавлять и удалять раздачи снаружи нельзя, это делает агент внутри сети Docker.

## Как узел качает

Раз в минуту агент отмечает heartbeat и забирает назначения. Для каждой раздачи он добавляет магнит в TorrServer и читает начало файла.

- Префикс в мегабайтах задается в админке (общий или свой у узла). `0` мегабайт означает проценты.
- Пустой магнит в назначении - это `magnet:?xt=urn:btih:<hash>`, дальше DHT. Ссылку с ключом трекера админка не сохраняет.
- Пока флаг выключен, список назначений пустой и агент снимает ранее скачанное.
- Закрепленная вручную раздача не снимается расчетом популярности. «Снять» в админке помечает ее удаленной.

Размер кэша TorrServer лежит в `torrserver.settings.json` (1 ГиБ, кэш на диске). Если префикс больше, поднимите `CacheSize` и лимит памяти сервиса `torrserver` в `docker-compose.yml`, затем выполните обновление.

## Обновление и удаление

Из нового каталога `ops/cache-node`:

```bash
sudo ./update.sh
```

Скрипт копирует файлы в `/opt/omp-cache-node` и пересобирает контейнеры. `/etc/omp-cache-node/config.env` не перезаписывается.

Остановить, не удаляя данные:

```bash
sudo ./uninstall.sh
```

Удалить контейнеры, тома, конфиг и каталог:

```bash
sudo ./uninstall.sh --purge
```

Отозвать доступ без удаления сервера: в админке «Отозвать». Старый токен перестает работать сразу. «Новый токен» снова показывается один раз, его нужно вписать в конфиг и перезапустить агент (`sudo ./update.sh`).

## Что выкатывать на биллинг

Нужен новый образ биллинга. При старте пройдет миграция `007_cache_nodes` (таблицы узлов, назначений и интереса). Переключатель по умолчанию выключен, так что выкладка образа сама кэш не включает. Этот узел на NUC через `deploy.sh` не ставится. Выкладку и включение флага делайте только после явного решения.
