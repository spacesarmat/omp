# OMP Design Editor: подключение и использование

## 1. Что это

Локальный визуальный редактор тем, макета и логики OMP. Он показывает реальные экраны приложения и позволяет менять оформление через токены и расположение элементов через перетаскивание, а не через редактирование CSS вручную. Режим «Логика» добавляет визуальное создание потоков: события, условия, действия и переменные связаны на canvas, проверяются пошаговым debugger и попадают в production только через явный экспорт.

Редактор работает только на вашем компьютере. Он не изменяет production-сервер, телефон, телевизор или плеер. Production-приложение применяет макет и логику только из проверенного экспорта (см. раздел 22).

## 2. Требования

- Node.js 24.
- Установленные зависимости проекта.
- Браузер с поддержкой современного JavaScript.

Если зависимости ещё не установлены, выполните в корне проекта:

```bash
npm install
```

## 3. Запуск и подключение

1. Откройте терминал в корне проекта.
2. Запустите:

```bash
npm run editor
```

3. Терминал покажет адрес вида:

```text
OMP Design Editor: http://127.0.0.1:PORT/#token=...
```

4. Откройте этот адрес целиком в браузере. Часть `#token=...` обязательна.
5. Не передавайте адрес с токеном другим людям и не публикуйте его.

Редактор доступен только по loopback-адресу `127.0.0.1`. Для остановки нажмите `Ctrl+C` в терминале.

## 4. Быстрый старт

1. Запустите редактор: `npm run editor` и откройте адрес с токеном (см. раздел 3).
2. В верхней строке выберите платформу `Windows` и страницу `settings` (Настройки). Режимы «Логика» и «Симуляция» доступны только для desktop-платформ и только на этой странице.
3. Нажмите «Логика» в верхней панели. Холст показывает поток выбранной страницы.
4. Добавьте узлы кнопками «+ Триггер», «+ Условие», «+ Действие», «+ Результат». Соединяйте выходы слева узла со входом следующего: выберите ветку `true` или `false` у условия, `default` или `error` у действия.
5. Настройте выбранный узел в инспекторе справа: путь и оператор условия, тип действия, экран, сообщение.
6. Откройте «Шаблоны» на холсте и нажмите «Вставить» у готового потока, если хотите начать с проверенного примера.
7. Нажмите «Симуляция» на холсте: debugger выполнит поток на моках, покажет trace и переменные.
8. Экспортируйте через раздел «Релиз и экспорт» справа: «Показать diff», затем «Экспортировать».

Подробности по каждому шагу - в разделах ниже. Ограничения и границы поведения собраны в разделе 23.

## 5. Основная рабочая область

- Верхняя панель содержит режимы «Дизайн», «Логика» и «Симуляция», сравнение, undo/redo и историю снимков.
- Слева находятся страницы, слои макета и шаблоны.
- В центре находится артборд с реальным preview или canvas потока в режиме «Логика».
- Справа находятся инспектор свойств, история снимков и экспорт.

Доступные действия на холсте дизайна:

- `V` - выбор элемента.
- `H` - перемещение холста рукой.
- `Ctrl` или `Cmd +` - увеличить масштаб.
- `Ctrl` или `Cmd -` - уменьшить масштаб.
- `Ctrl` или `Cmd 0` - вписать макет.
- `Ctrl` или `Cmd Z` - отменить.
- `Ctrl` или `Cmd Shift Z` - повторить.

Стрелки, `Home` и `End` перемещают фокус по toolbar. Горячие клавиши работают и при фокусе внутри preview, но не перехватывают ввод в текстовых полях.

## 6. Выбор платформы, страницы и формата

Верхняя строка позволяет выбрать:

- Windows, macOS или Linux.
- Android phone.
- Android TV.
- LG webOS.
- Страницу.
- Формат landscape или portrait, если платформа это поддерживает.
- Состояние и язык preview.

Для TV всегда используется логический размер 1920x1080: на телевизоре с 4K интерфейс масштабируется из этого же логического макета. Для desktop доступны 1280x720 и 720x960. Для phone portrait используется 720x960, landscape - 960x720.

При смене платформы или страницы выбор элемента и состояние сбрасываются, чтобы не применить чужой шаблон к новому экрану. Phone и TV в редакторе - это preview и цели production-потоков: node canvas для них не открывается, редактирование потоков ведётся на desktop-цели.

## 7. Редактирование элемента

1. Выберите страницу слева.
2. Выберите шаблон или нажмите на элемент в preview.
3. В инспекторе измените цвет, текст, отступы, размер шрифта или радиус.
4. Проверьте результат в preview.
5. Используйте undo для возврата значения.

Доступные общие шаблоны:

- Страница.
- Кнопка.
- Поле ввода.
- Карточка.
- Строка настройки.

На desktop также доступны боковое меню, пункт меню, контент, кнопка продолжения и карточка сервера.

Панель показывает только те шаблоны, которые существуют на текущей платформе и странице.

## 8. Область переопределения

Селектор `Область` определяет, к какому уровню применяется изменение:

- `platform` - для всей платформы.
- `screen` - для одной страницы.
- `element` - для выбранного шаблона.
- `format` - для landscape или portrait.
- `state` - для выбранного интерактивного состояния.

Цепочка наследования показана в инспекторе. Кнопка `Сбросить override` удаляет только текущий уровень и не удаляет базовую тему.

## 9. Состояния

Селектор `Состояние` меняет состояние preview:

- `default`.
- `hover`.
- `focus`.
- `active`.
- `disabled`.
- `error`.

Для сохранения отдельного оформления состояния выберите `state` в `Область`, затем нужное состояние и измените свойства. При переключении состояния preview применяются только overrides этого состояния.

## 10. Макет: flow и absolute

Элементы макета используют два способа размещения:

- `flow` - элемент живёт в контейнере и занимает позицию в порядке контейнера. Перетаскивание flow-элемента внутри контейнера меняет порядок.
- `absolute` - элемент закреплён на координатах относительно родителя. Перетаскивание двигает элемент по артборду.

Перетаскивание выполняется инструментом выбора (`V`): зажмите элемент и двигайте указатель. При перетаскивании элемент прилипает к направляющим соседних элементов, границ артборда и безопасной области TV. Удерживайте `Alt`, чтобы отключить прилипание на время движения.

Размер меняется ручками по углам и сторонам выбранного элемента. Для flow-элементов размер остаётся в рамках правил контейнера, для absolute - это ширина и высота в пикселях артборда.

Те же значения доступны числами в инспекторе макета справа: режим, порядок, выравнивание, отступы, размер и z-index.

## 11. Множественный выбор

Несколько элементов выбираются так:

- `Shift +` клик по элементу добавляет его к выделению или убирает из него.
- Рамка на пустом месте холста выделяет элементы внутри неё.

При выбранной группе справа открывается инспектор множественного выбора:

- Выравнивание: `start`, `center`, `end`, `stretch`.
- Распределение: `start`, `center`, `end`, `space-between`, `space-around`.
- Перетаскивание любого выделенного элемента двигает всю группу.

Для flow-элементов одного контейнера групповое выравнивание записывается в контейнер, для absolute-элементов - в сами элементы.

## 12. Слои

Панель `Слои` слева показывает дерево макета текущей страницы:

- Поле `Фильтр слоёв` ищет слой по имени.
- Кнопки `Копировать выделенные слои` и `Вставить слои` переносят выделенные узлы внутри страницы.
- `Переименовать слой` меняет имя узла.
- `Скрыть слой` убирает узел из preview и экспорта, `Показать слой` возвращает.
- `Заблокировать слой` запрещает выбор и правку узла на холсте, разблокировка возвращает.
- `Дублировать слой` создаёт клон рядом с оригиналом. Клон виден в preview и попадает в production runtime после экспорта.

Скрытые и заблокированные узлы пропускаются групповыми операциями и экспортом не теряют своё состояние.

## 13. Стили и пресеты

Раздел `Библиотека стилей` работает с оформлением выбранного элемента:

- `Копировать стиль` запоминает оформление элемента для переноса на другой элемент.
- Поле `Имя preset` и сохранение создают именованный пресет из текущего оформления.
- `Применить` ставит пресет на выбранный элемент.
- `Обновить использования` перезаписывает все элементы, где этот пресет применён.
- `Удалить` убирает preset без изменения элементов.
- Поиск `Например --omp-color-panel` показывает, где используется выбранный токен.

Сброс рядом с каждым свойством удаляет только override этого свойства на текущем уровне.

## 14. Сравнение

Верхняя панель предлагает два способа сравнения:

- Кнопка `До/После` показывает исходную тему вместо текущей и обратно. В режиме `До` preview не редактируется.
- Кнопка `Платформы` открывает рабочую область, где платформы идут рядом на одном артборде, а текущая страница подсвечивается. Повторный нажатие скрывает её.

Пока открыт снимок сравнения или режим `До`, инспекторы, слои и буфер слоёв работают в режиме чтения, чтобы правка не попала не в тот документ. То же относится к canvas потока: при сравнении с базовой темой правка узлов выключена, кнопки добавления и удаления отключены, а копирование остаётся доступным.

## 15. Доступность

Панель `Доступность` в разделе экспорта показывает проверки текущего макета:

- контраст текста и фона;
- минимальный размер шрифта;
- геометрия: выход за границы артборда, пересечения, обрезку родителем и выход за безопасную область TV.

Проблемы выводятся списком с уровнями `error` и `warning`. Экспорт с неподтверждёнными предупреждениями геометрии заблокирован: без отметки `Экспортировать с предупреждениями геометрии` кнопка экспорта остаётся неактивной. Ошибки доступности устраняйте до экспорта.

## 16. Снимки и история

Кнопка с иконкой снимка в верхней панели открывает историю.

Создание:

1. Введите имя в поле `Имя снимка`.
2. Нажмите `Создать снимок`.
3. Появятся тема и правила текущего момента.

Действия:

- `Сравнить` - показывает snapshot вместо текущей темы.
- `Текущий` - возвращает текущую тему.
- `Восстановить` - применяет снимок и создаёт обычный undo step.
- `Удалить` - удаляет только выбранный снимок, удаление также отменяется через undo.

Одновременно хранится не более 10 снимков. Пустое имя и превышение лимита показывают ошибку без удаления предыдущих снимков.

## 17. Режим «Логика»: холст потока

Режимы «Логика» и «Симуляция» доступны только при выбранной desktop-платформе (Windows, macOS или Linux) и только на странице `settings`. На других платформах и страницах кнопки режимов отключены, а режим автоматически возвращается к «Дизайн». Phone и TV показывают preview и production-потоки, node canvas для них не предусмотрен.

В режиме «Логика» центральная область показывает canvas потока текущей страницы. Поток хранится в виде типизированного документа: узлы четырёх видов (`trigger`, `condition`, `action`, `result`), связи с ветками и шаги с условиями и действиями. Произвольный JavaScript, сетевые запросы и секреты в потоки вставить нельзя.

Панель инструментов холста:

- `+ Триггер`, `+ Условие`, `+ Действие`, `+ Результат` - добавляют узел в центр видимой области. Клавиша `Insert` добавляет условие.
- `-` и `+` - масштаб от 0.4 до 2.
- `Авторазметка` - выравнивает узлы по колонкам.
- `Шаблоны` - открывает библиотеку готовых потоков (см. раздел 19).
- `Симуляция` - переходит к симуляции и debugger.

Навигация по canvas: перетаскивание пустого места двигает вид, правый нижний угол показывает minimap с точками узлов, фон размечен сеткой.

Добавление первого узла создаёт для страницы graph-правило с событием `screen.enter`. В одном графе может быть только один триггер; повторное добавление триггера покажет ошибку. Событие триггера и его элемент показаны в инспекторе и не редактируются: событие определяет правило, а не отдельный узел.

Связи строятся от выхода к входу: зажмите порт справа узла и отпустите над входом слева следующего узла. Ветки зависят от вида узла:

- Триггер имеет ветку `default`.
- Условие имеет ветки `true` и `false`.
- Действие имеет ветки `default` и `error`.
- Результат - терминальный узел без выходов, он собирает итог выполнения.

Панель не позволит создать петлю на сам узел, дубликат связи или цикл: такая попытка завершится ошибкой с кодом, а документ не изменится. Если подходящей ветки нет, выполнение просто завершается.

Перетаскивание узла мышью двигает его, вся группа при мульти-выборе двигается вместе. Позиции узлов влияют только на вид canvas, на выполнение они не влияют. Один drag, одно добавление, одна вставка или одно удаление - один шаг undo.

Клик по узлу открывает его инспектор справа и подсвечивает связанный экран или элемент в design-режиме. Кнопка `Показать в дизайне` в инспекторе переводит в режим «Дизайн» с выбранной целью узла: экран элемента для триггера, экран назначения для действий навигации.

Пока не выбран ни один узел, инспектор показывает `Карту переходов` - список всех правил документа с экранами, условиями и действиями. В той же колонке остаётся простой редактор правил кнопки `settings-continue`: событие `click`, условие по подключению сервера и действия `navigate`, `back`, `toast`. Он нужен для совместимости со старыми документами и редактирует только одну кнопку; остальные потоки собираются на canvas.

## 18. Условия, действия и переменные

Инспектор узла (`Узел: Триггер`, `Узел: Условие`, `Узел: Действие`, `Узел: Результат`) показывает только поля, относящиеся к выбранному узлу:

- `Метка` - имя узла на canvas.
- Триггер - только уведомление с событием и элементом правила.
- Условие - `Путь`, `Оператор` и `Значение`. Пути: `server.connected`, `target`, `screen.current`, `network.online`, `account.signedIn`, `playback.state`, `download.state` и `variable.<id>` для каждой переменной документа. Операторы: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `contains`, `exists`. Значение проверяется до сохранения: для числовых операторов нужно число, для boolean-путей - только `true` или `false`; иначе поле покажет ошибку (`NUMBER_REQUIRED` и другие коды).
- Действие - `Действие` из списка типов: `navigate`, `back`, `openScreen`, `toast`, `dialog`, `playback.playPause`, `playback.stop`, `playback.nextEpisode`, `queue.add`, `queue.replace`, `server.connect`, `server.reconnect`, `server.retry`, `source.retry`, `source.next`, а также `variable.set`, когда в документе есть переменные. Для навигации выбирается `Экран` из маршрутов desktop, для `toast` и `dialog` - `Сообщение`, для `dialog` ещё `Заголовок`. Пустой текст `toast` не сохраняется (`TOAST_REQUIRED`).
- `variable.set` - выбор `Переменная` и `Значение` её типа: boolean переключателем, number числом, enum выбором из разрешённых значений, string текстом.

Переменные документа типизированы (`boolean`, `string`, `number`, `enum`) и объявляются вместе с потоком: сегодня в документ они попадают из шаблонов (кнопка `Шаблоны` добавляет недостающие переменные автоматически). Переменные участвуют в условиях через путь `variable.<id>` и меняются действием `variable.set`. Значения переменных живут только в контексте выполнения текущей сессии приложения и не сохраняются между запусками: позицию воспроизведения и историю страниц хранят существующие механизмы приложения, а не переменные потока.

Узел `result` без собственного шага - терминальный сборщик итога: итоговый route, переменные, `toast` и trace. Явный результат не обязателен: ветка может завершаться terminal action, такие действия помечены в схеме документа.

## 19. Шаблоны потоков

Кнопка `Шаблоны` на canvas открывает библиотеку из пяти проверенных потоков. У каждого карточка с описанием и кнопкой `Вставить`:

- `Подключение сервера` - кнопка продолжения: при подключённом сервере сразу открывает каталог, иначе подключает сервер.
- `Повтор при пропадании сети` - при событии `network.offline` показывает ошибку и повторяет подключение к серверу.
- `Очередь серий` - выбор серии добавляет её в очередь и запускает следующую серию.
- `Запасной источник` - пробует другой источник воспроизведения, при неудаче показывает ошибку.
- `Возврат с сохранением позиции` - на уходе со экрана запоминает route, позицию и элемент, на входе возвращает к ним.

Вставка добавляет правила, узлы, связи и переменные шаблона в конец документа со свежими уникальными id, поэтому один шаблон можно вставлять несколько раз. Исходный шаблон от ваших правок не меняется.

## 20. Симуляция и debugger

Кнопка `Симуляция` на canvas или в инспекторе переключает редактор в режим «Симуляция». В нём доступны два инструмента.

Простая симуляция - кнопка `Нажать «Продолжить»` выполняет клик по кнопке продолжения с учётом галочки `TorrServer подключён` и показывает итоговый экран, `toast` и trace сработавших правил.

Debugger - панель под симуляцией для graph-правил текущего экрана:

- Селектор `Правило` выбирает отлаживаемый поток.
- Блок `Моки` задаёт входные состояния без реальных вызовов: `Сервер подключён`, `Сеть онлайн`, `Аккаунт вошёл`, плеер (`idle`, `playing`, `paused`, `stopped`) и загрузка (`idle`, `active`, `completed`, `failed`). Моки не меняют настройки приложения.
- Кнопки: `Старт` выполняет поток до точки остановки или конца, `Пауза` останавливает выполнение, `Шаг over` выполняет до следующего действия, `Шаг into` - до следующего узла, `Стоп` прерывает выполнение, `Сброс` очищает trace и состояние, `Повтор и сравнение` запускает поток заново и сравнивает новый trace с предыдущим.
- `Точки остановки` - галочки на правило и на каждый узел.
- Блоки `Переменные` и `Trace` показывают текущие значения и журнал шагов: условие с результатом, ветку, действие и ошибку.
- Различие двух trace подсвечивается строкой `Первое различие: шаг N` с обеими записями.

Смена страницы или формата сбрасывает сессию debugger, чтобы состояние не переходило между разными экранами.

## 21. Проверки логики

Документ проверяется до сохранения и перед экспортом. Проверки ловят: связи в несуществующий узел, self-loop, циклы, дубли веток, недостижимые узлы, отсутствие триггера или пути к терминальному действию, несколько триггеров в одном графе, несовпадение типов значений условий и `variable.set`, неизвестные переменные, пустые сообщения `toast` и `dialog`, навигацию по неизвестным маршрутам, дубли id правил и мёртвые правила. Проблемы выводятся с кодами (`CYCLE`, `UNREACHABLE_NODE`, `WRONG_VALUE_TYPE` и другие) в панели логики и в ответе экспорта. Ошибки логики блокируют экспорт: он завершится ошибкой `INVALID_FLOW` со списком проблем, а кнопка `Экспортировать` дополнительно остаётся неактивной, пока экспорт блокирован ошибками доступности, неподтверждённой геометрией или превью не черновой темы.

Правила без graph продолжают работать по старой схеме в исходном порядке: если сработало старое правило, graph-правила этого события не выполняются.

## 22. Экспорт и production

Раздел `Релиз и экспорт` позволяет указать версию и канал `beta` или `stable`.

Перед экспортом:

- проверьте все платформы и состояния;
- убедитесь, что нет ошибок доступности;
- подтвердите предупреждения геометрии;
- проверьте список изменённых токенов;
- сохраните снимок для возможного отката.

`Область экспорта` ограничивает запись:

- `Всё` - все платформы и страницы, как раньше.
- `Страница` - только текущая страница и платформы, где она есть.
- `Компонент` - один узел по node id и затронутые им платформы.

Кнопка `Показать diff` (только при запущенном сервере) показывает список файлов с действиями `create`, `update`, `unchanged` и файлы вне области, которые не изменятся. Для логики diff дополнительно раскрывает изменённые части документа: правила, узлы, связи и переменные с добавленными, удалёнными и изменёнными элементами. Сам diff только читает и ничего не пишет.

Экспорт создаёт проверенные файлы темы, правил и CSS, делает бэкап изменяемых и удаляемых файлов и восстанавливает его при сбое. Он не создаёт production-релиз и не выполняет деплой. Для macOS и Linux пакет помечается как недоступный. Экспорт отклоняется с ошибкой и списком проблем, если не подтверждены предупреждения геометрии, есть ошибки доступности, превью показывает не черновую тему или проверки логики нашли ошибки.

Production-приложение применяет макет из сгенерированного модуля `design/generated/layout.ts`, а логику потоков - из `design/generated/flow.ts`. Эти модули обновляются только явным экспортом: автосохранение черновика и простое открытие редактора production не меняют. Откат выполняется восстановлением файлов из бэкапа экспорта или возвратом коммита в `design/`.

## 23. Ограничения

- Production меняется только после явного экспорта. Отладка, моки, симуляция и автосохранение черновика не влияют на production-приложения.
- Переменные потоков живут в контексте выполнения текущей сессии и сбрасываются вместе с ним. Между запусками приложения они не сохраняются.
- Редактирование потоков - только desktop-цель и страница `settings`. Phone и TV в редакторе - это preview и цели production-потоков, а не поверхности node editing.
- На phone действие `queue.add` возвращает документированную ошибку: встроенный плеер принимает очередь целиком при запуске, а player-link протокол не имеет команды append. Используйте `queue.replace` с экрана торрента.
- На TV события `playback.paused` и `playback.finished` зависят от свежести snapshot зарегистрированного плеера: он обновляется по существующему периоду phone-link и на сменах состояния плеера. Без зарегистрированного плеера события паузы и завершения не приходят.
- Событие `download.failed` не отличает удаление торрента пользователем от потери загрузки: торрент, исчезнувший до завершения, всегда даёт `download.failed`. Правила на него должны учитывать текущий экран.
- Потоки выполняются синхронно и детерминированно: произвольный JavaScript, произвольные HTTP-запросы, асинхронные цепочки и параллельное выполнение не поддерживаются. Ошибки в асинхронных приложенческих API error-ветками не обрабатываются - они остаются в существующих обработчиках приложения.
- Один event - один trace: не более 32 шагов на событие, повторный запуск триггера ограничен cooldown, фоновые timer-потоки стартуют не более 16 и только после экспорта.

## 24. Безопасность

- Preview использует тестовые данные и не выполняет реальные сетевые запросы.
- Внешние fetch и XHR получают заглушку 503, same-origin запросы продолжают работать.
- Production App, биллинг, обновления и фоновые сервисы не запускаются.
- Не вставляйте произвольный JavaScript, HTML или CSS в документы темы.
- Не изменяйте `baseCommit` вручную.
- Не публикуйте локальный токен редактора.

## 25. Если что-то не работает

- Проверьте, что сервер запущен через `npm run editor`.
- Откройте адрес с токеном целиком.
- Обновите страницу после изменения кода редактора.
- Проверьте, что выбранная страница существует на текущей платформе.
- Если preview не меняется, проверьте область и состояние override.
- Если элемент не выбирается, проверьте, не заблокирован ли слой.
- Если правка недоступна, проверьте, не открыт ли режим `До` или сравнение снимка.
- Если значение не сохраняется, проверьте сообщение об ошибке и нажмите `Повторить`.
- Если недоступны «Логика» и «Симуляция», проверьте, что выбрана desktop-платформа и страница `settings`.
- Если связь не создаётся, читайте код ошибки на canvas: петля, цикл, дубликат или неподходящая ветка не сохраняются.
- Если узел не удаляется через `Delete`, проверьте, не открыт ли режим сравнения с базовой темой.
- Если экспорт неактивен, проверьте ошибки доступности, подтверждение геометрии, что превью показывает черновую тему и список проблем логики.
- Если страница показывает `package unavailable`, это ограничение пакета, а не ошибка темы.
