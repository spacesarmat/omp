# Аудит админки биллинга

Предложение. Код продукта не менялся. Вливать этот PR не нужно.

Проход: 19.11.2026, локальный Postgres 16 (в CI и на NUC - 17), Node 24, демо-данные, Playwright (Chromium). Открыты все 28 разделов, вход, палитра, карточка пользователя, подтверждение отзыва устройства, редактор ответа бота, ширина 1440 и 390. Консоль браузера пустая, ответов 4xx/5xx нет. Лог контейнера NUC не открылся: без `BILLING_DOCKER_PROXY_URL` список контейнеров пуст, кнопка «Лог» не рисуется. Сборка админки - уже лежащий `ops/billing/public` (JS 1.0 МБ, gzip 302 КБ). За время прохода файлы админки и курсов на `main` не менялись.

## 1. Что уже есть

Оболочка: React 19, Vite 6, Tailwind 4, набор в духе shadcn (Radix, CVA), TanStack Query и Table, cmdk, Recharts. Тёмная тема зашита в CSS, переключателя нет. Отдельного i18n у панели нет: интерфейс русский, английский только в журнале изменений и в редакторе ответов бота. Маршрутизатора нет: раздел - `useState`, в адрес попадает только первый `?tab=` и `?id=`.

Сервер отдаёт `ops/billing/public` из того же процесса, что и API (`/admin/`). Отдельного сервиса на NUC нет.

## 2. Десять проблем интерфейса

1. Навигация не держится. 28 пунктов одним списком. Выбор раздела не пишет адрес, «Назад» и обновление возвращают на Обзор. Палитра (`admin/src/components/palette.tsx`) не знает «Финансы», «Донаты» и «Ответы бота», хотя они есть в меню.
2. Два поиска. В шапке палитра, на Обзоре отдельная форма «Найти». В палитре тип записи по-английски: `account`.
3. Курсы разложены по двум экранам. Рублёвая база - «Настройки», автокурс - «Донаты», ручные тарифы звёзд и крипты снова в «Настройках». Текст на «Донатах» прямо говорит: при старом курсе донат прячет способ, подписка берёт ручной тариф.
4. Подтверждения разные. Отзыв устройства - встроенный вопрос и «Да, отозвать». Часть действий - `window.confirm`. Без вопроса: «Быстрое промо» на Обзоре, «Отменить» в журнале рефералов, «Скрыть комментарий» у доната. Реферальные числа сохраняются по уходу из поля.
5. Журнал рефералов нечитаемый. Строка вида `id · Дни · granted · 7 дн.` Сырой id, английский статус, отмена без объяснения, что дни и баланс вернутся.
6. Журнал аудита показывает код действия как есть (`settings`, `device`). Смена курса пишется одной строкой «Донат», без старого и нового числа. Откат не включает курсы, звёзды, крипту, донат и рефералку (`ROLLBACK_KEYS` в `desk.mjs`).
7. Карточка пользователя выпадает из меню: сверху только «К списку» и «Назад». В списке подписка - «активна» или «нет», без даты. Чекбоксы есть, массовое действие одно: «Открыть первого».
8. Узкая ширина. Меню не шторка, а блок над страницей (`aside` в потоке). В шапке на 390px остаются Ctrl+K, «в эфире» и «полный доступ». Полоса прокрутки скрыта у всей страницы (`index.css`), длинные «Настройки», «Донаты» и «Ответы бота» не показывают, где вы находитесь.
9. Пустые операционные экраны. NUC без прокси пишет `нет BILLING_DOCKER_PROXY_URL` и не предлагает лог. «Сбои» без карточки и заголовка: одна серая строка «Сбоев нет». Мониторинг честно пишет, что расписание на этом экземпляре выключено, но кнопка «Проверить сейчас» стоит рядом без списка проверок, пока их нет.
10. Редактор ответов бота - свой оверлей, не общий `Modal`. Плейсхолдеры шаблона на английском (`{status}`, `{admin_hint}`). «Источники» и «Сервисы» открывают одну форму. «Выручка» и «Финансы» - два графика одних оплат.

Локально API отвечали за миллисекунды. Тяжёлое место - не таблица, а «Изменения»: `GET /admin/api/changelog` отдал 472 КБ. На NUC первая загрузка ещё ждёт GitHub.

## 3. Чего не хватает

Имеет смысл добавить, не плодя вторую панель:

- Один поиск: экраны, человек, устройство, платёж, донат, промо, реферал. Сейчас доната и промо в `searchDesk` нет.
- Карточка 360: подписка, устройства, оплаты, донаты, рефералы и аудит этого человека на одной ленте. Куски уже есть, ленты нет.
- Журнал с фильтром и диффом. Отдельный вид для смены цены и курса: было, стало, источник, кто.
- Массовые действия с подтверждением и числом затронутых: дни, сообщение, отзыв промо. Не «Открыть первого».
- Одна денежная сводка: подписки и донаты, способ, холды. Сейчас это Обзор, Финансы, Выручка и Донаты.
- Роли по зонам. Сейчас два режима: полный и чтение по Telegram id, а вход с машины всегда полный. Деньги и перезапуск NUC логично отделить от чтения.
- Один способ опасного действия: вопрос, что изменится, «Да» в интерфейсе, сервер по-прежнему требует `confirm=yes`.

Не делать в этом проходе: новый биллинг, второй бот, вебхук Telegram.

## 4. Курсы и оплата

### Как считается сейчас

Рублёвая база в «Настройках»: `priceRub`, `extraDeviceRub`, период, база устройств. Кнопки доната - свой список рублей (`donate.amounts`), не цена подписки.

Общая книга `settings.rates` (PR 399, `src/rates.mjs`):

| Величина | Источник | Если источник молчит |
| --- | --- | --- |
| USDT, TON, BTC в рублях | Crypto Pay `getExchangeRates` на боевом или testnet-хосте | CoinGecko `simple/price` |
| USD/RUB | JSON ЦБ `cbr-xml-daily.ru` | Курс USDT/RUB |
| Рубль за 1 звезду | `starUsd` (по умолчанию 0.013, вывод через Fragment) умножить на USD/RUB | Пока доллар свежий, звезда считается. Своего курса Stars у Telegram нет |

Обновление примерно каждые `refreshMin` (по умолчанию 12, в форме это число не меняется) и перед счётом доната, если кэш старый. Один запрос на всех. Неудача не затирает последнее годное число и всё равно ставит `fetchedAt`, чтобы не долбить хосты. Число старше `maxAgeMin` (по умолчанию 24 часа, в форме - часы) не используется. Наценка `markupPercent` уменьшает рублёвый курс: донор отправляет больше актива. Ноль и курс вне диапазона отбрасываются.

Округление, уже в коде:

- Звёзды: `ceil(рубли / рубль_за_звезду)`, целое, без комиссии сверху (`starList`, `starsForRub`).
- Крипта полной суммы: half away from zero, USDT 2 знака, TON 4, BTC 8 (`formatAsset`).
- Крипта после зачёта: пол вниз, чтобы скидка не увеличила счёт (`formatAssetFloor`).
- ЮMoney: это уже рубли. `grossUp` поднимает сумму на комиссию кошелька (1% с получателя) или карты (3% со списания), в копейках. Отдельного валютного курса нет и не нужно.

`paymentPricing` кормит и донат, и подписку. При свежем автокурсе звёзды и крипта подписки считаются от `priceRub` / `extraDeviceRub`. ЮMoney считает от тех же рублей плюс комиссия.

### Разрыв с требованием

Требование: все донаты и остальные способы сидят на автоматическом курсе от цен в «Система - Настройки».

Движок для звёзд и крипты уже общий. Не выполнено другое:

- Автокурс можно выключить по активу. Тогда живут ручные `starsPrice`, `starsExtra`, `cryptoUsdt` и `cryptoRate*`. Это вторая цена, она может не совпасть с `priceRub`.
- Устаревший курс прячет способ только у доната. Подписка молча берёт ручной тариф.
- Рычаги курса лежат на «Донатах», база - на «Настройках». Интервал обновления из формы не задаётся.
- Аудит сохранения - слово «Донат». Откат курс не хранит. Нет записи «кто закрепил число и до когда».

### Как сделать

Одна цена в «Настройках»: подписка, доп. устройство, кнопки доната, минимум и максимум. Всё в рублях.

Одна книга курсов, та же, что сейчас. Счёт и доната, и подписки идёт через одну функцию: рубли заказа, потом актив.

- Звёзды: `ceil`, как сейчас. `starUsd` остаётся настройкой (0.013 - получение, ближе к 0.02 - цена покупки), не вторым тарифом.
- Крипта: те же знаки. Полная сумма - half away from zero, сумма после зачёта - пол вниз.
- ЮMoney: курс 1 и `grossUp`. В «Настройках» рядом с ценой показывать кошелёк и карту к оплате, чтобы комиссия не всплывала только в боте.

Если источник недоступен: оставить последнее годное число до `maxAge`. Дальше способ скрыт и у доната, и у подписки. Ручной тариф запасным путём не работает. В панели видно источник, возраст и что способ скрыт.

Закрепление курса - отдельная строка, не выключатель «навсегда»: актив, число, причина, срок, кто. После срока снова авто. Каждая смена книги и каждое закрепление пишут в аудит старое, новое и источник. Эти поля входят в откат.

Кэш остаётся в `settings.rates` в Postgres. Отдельного сервиса нет. Обновление: интервал 5-60 минут (поле в «Настройках», по умолчанию 12) и один общий запрос перед счётом, если кэш старше интервала.

Тесты рядом с `test/rates.test.ts`, `test/donate.test.ts`, `test/payMethods.test.ts`: подписка и донат дают одно число от одной базы; протухший курс прячет оба; ЦБ падает - берётся USDT; Crypto Pay падает - CoinGecko; закрепление истекает; аудит содержит оба числа.

## 5. Стек

Оставить React + Vite + Tailwind + текущие компоненты shadcn + TanStack Query и Table. Добавить TanStack Router. Не переезжать на Refine, React Admin, SvelteKit или Nuxt.

Почему не переезд:

- Панель уже этот стек. Сборка кладётся в `ops/billing/public` и отдаётся контейнером billing. Новый фреймворк не убирает ни NUC, ни бота, ни курсы.
- Экраны не CRUD. Лог контейнера, шаблоны бота, SSE «в эфире», книга курсов. React Admin и Refine придётся обходить на каждом таком экране.
- SvelteKit и Nuxt либо тащат второй сервер, либо всё равно собираются в статику. На NUC второй процесс не нужен.
- Бандл уже 302 КБ gzip. Переписывание 28 экранов раздует его и остановит правки курсов.

Router нужен: адрес раздела, «Назад», обновление. Панели переносятся по одной, серверные маршруты `/admin/api/*` не меняются.

### Фазы

Каждая фаза сама по себе рабочая. Код только после отдельного «да».

1. Безопасный интерфейс на текущем коде. Адрес раздела. Палитра совпадает с меню. Одинаковое подтверждение у промо, отмены реферала и скрытия доната. Русские статусы рефералов и коды аудита. Заголовок у пустых «Сбоев» и понятный текст NUC без имени переменной. Меню на узкой ширине - шторка. Один PR, без новых библиотек.
2. Единый курс из раздела 4. Форма в «Настройках», «Донаты» только лента и флаги приёма. Сервер, аудит, тесты vitest. Один PR.
3. TanStack Router вокруг текущих панелей, по разделу. Тот же `public/`, тот же контейнер.
4. Карточка 360, фильтр журнала, массовые действия с числом затронутых. Роли не расширять, пока не согласован список зон.
5. Проверки. Playwright: вход, каждый раздел открывается, подтверждение отзыва не шлёт запрос до «Да», сохранение курса показывает число подписки. Компонентные тесты форм доната и рефералов. Джоба `billing` уже поднимает Postgres.
