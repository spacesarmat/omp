# LG Content Store: подготовка пакета и материалов

Цель: постоянная установка OMP на LG webOS без режима разработчика, чтобы webOS не удалял приложение после 1000 часов (см. инцидент 18.11.2026). Оперативные меры уже влиты (#434 кнопка «Продлить режим» + баннер, #435 обновление с телефона); этот документ - про постоянный путь через магазин LG.

Разделение работ: я готовлю пакет и материалы, Andy регистрирует seller-аккаунт и проходит ревью LG.

## 1. Оценка осуществимости (читать первым)

Два риска, которые нужно решить до подачи, иначе ревью LG почти наверняка откажет:

- **Контент-политика.** OMP ищет раздачи на публичных трекерах (rutor, rutracker, nnmclub, Kinozal и др.) и стримит их через TorrServer. Магазин LG отклоняет приложения, облегчающие доступ к защищённому авторским правом контенту. Позиционирование «плеер для собственного TorrServer / домашних медиа» само по себе не снимает риск, пока в приложении есть поиск по публичным трекерам. Вероятное решение - отдельная store-сборка без поиска по публичным трекерам: только каталог собственного сервера пользователя, M3U/HLS и локальные медиа. Это продуктовое решение Andy.
- **Зависимость от TorrServer.** OMP нужен TorrServer в домашней сети. Для ревью LG тестировщику понадобится рабочий сервер и контент. Нужно приложить инструкцию для QA и, возможно, демо-стенд. Без этого приложение не пройдёт функциональное тестирование.

Прочее: OMP поддерживает webOS 4.0+ (Chrome 53). Магазин может требовать более свежие стандарты webOS - уточнить при подаче.

Вывод: перед сборкой пакета решить с Andy, делаем ли store-вариант без публичного поиска. Остальные материалы ниже готовятся в любом случае.

## 2. Что требует подача в LG Content Store

Точные спецификации (размеры иконок, число скриншотов, форматы) уточняются в LG Seller Lounge при создании приложения; ниже - состав, который нужен в типовом случае.

- Seller-аккаунт: seller.lgappstv.com (регион, тип аккаунта, реквизиты). Регистрирует Andy.
- Пакет приложения: web-приложение webOS (ipk) либо формат, который примет Seller Lounge для TV.
- Метаданные: название, короткое и полное описание, категория, ключевые слова, языки, страны распространения, возрастной/контентный рейтинг.
- Ассеты: иконки нескольких размеров, скриншоты интерфейса ТВ (обычно 1920x1080), при необходимости превью-видео.
- Юридическое: URL политики конфиденциальности, условия использования, контакт поддержки.
- Материалы для QA: инструкция по запуску (TorrServer + сеть), при необходимости тестовый доступ.
- Ревью LG: функциональное тестирование и контент-ревью; ответы на замечания.

## 3. Что уже есть в репозитории

- Иконки: `webos/icon.png`, `webos/largeIcon.png` (и beta-варианты `webos/beta/`). Логотип `assets/logo.svg`.
- Скриншоты: `docs/screenshots/` (ТВ и Android). Для магазина нужны именно экраны LG ТВ в требуемом разрешении; их можно снять тем же CDP-инструментом, что использовался для #434 (vite dev + headless Chrome 3840x2160/1920x1080).
- Сайт `omp-player.online` - можно разместить политику конфиденциальности и условия.
- Сборка webOS-пакета: `npm run build` + `node scripts/package.mjs` (ares-package), `webos/appinfo.json`.

- appinfo/метаданные под store (id, title, vendor, разрешения).

## 5. Черновики метаданных (для обсуждения)

Название: OMP - Open Movie Player (или «OMP - медиаплеер», если магазин требует локальное название).

Короткое описание (ru): «Медиаплеер для вашего TorrServer: фильмы и сериалы из домашней сети на телевизоре LG.»

Полное описание (ru), вариант без акцента на публичном поиске:
«OMP воспроизводит медиатеку вашего TorrServer на телевизоре LG: каталог с категориями и сериалами по сезонам, продолжение с места остановки, аппаратный декодер телевизора, дорожки, субтитры и главы. Телефон работает как пульт. Поддерживаются плейлисты M3U/HLS. OMP не содержит каталога контента - он подключается к серверу, который вы запускаете сами в своей сети.»

Категория: Photo & Video / Entertainment (уточнить в Seller Lounge).

Важно: формулировки выше намеренно не упоминают публичные трекеры. Если store-сборка сохраняет поиск, описание и контент-рейтинг должны отражать это честно, и риск отказа остаётся высоким.
