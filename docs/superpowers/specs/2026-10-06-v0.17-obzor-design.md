# OMP 0.16 — «Обзор» в «Каталоге» (design)

Date: 2026-10-05. Mockups (approved): https://claude.ai/artifact/VatvCxrBZ77EVjsfJyA8EX
Delivered first as the beta 0.17.0-beta.1 (beta channel since 0.15.5), then as 0.17.0.

## Goal

A Seerr-like way to discover films and series inside OMP: browse the newest titles from TMDB, open a card with the
description, rating, cast and seasons, then either find torrents for it with the existing search or subscribe to it
(«Хочу посмотреть»). Phone only in 0.16; the TV gets «Обзор» later (separate spec).

## Scope

In:
- «Каталог» tab on the phone gets a segmented switch «Мои / Обзор». «Мои» is today's library, unchanged (its chips
  «История / Все / Фильмы / Сериалы» stay). «Обзор» is new. The switch position is remembered (per device).
- «Обзор» home: one feed «Новинки» with chips «Все / Фильмы / Сериалы». Films: recent digital releases; series:
  series with new episodes/seasons now. Two-column poster grid, rating badge, «В медиатеке» badge when the title is
  already in the library. Infinite scroll by pages (TMDB page = 20).
- Search in «Обзор»: the header search icon opens a field; results are TMDB films and series (multi search, Russian),
  plus a link «Искать «<запрос>» на трекерах» that opens «Добавить» with the query.
- Film card: backdrop, poster, title, year, genres, runtime, TMDB rating, overview (collapsed to 4 lines, «Ещё»),
  cast (first 8 with photos), buttons «Найти раздачи» (primary) and «Хочу посмотреть».
- Series card: the same plus the seasons list (number, episode count, year; state «выходит: N из M» while airing,
  «В медиатеке» when matched). «Найти раздачи» on the card searches the series; on a season row, that season.
- «Найти раздачи»: opens «Добавить» with a ready query and runs the search. Film: «<русское название> <год>»;
  series: «<русское название>»; season: «<русское название> <N> сезон». Everything after is the existing flow.
- «Хочу посмотреть»: a sheet with the query (same rule as above) and quality chips «Любое / 1080p / 4K», button
  «Подписаться» → `addSubscription` in the monitoring («Новое»), notifications on. When a subscription with the same
  query exists, the card shows «Слежу за фильмом / за серией» instead and opens that subscription.
- Torrent filters (the results of «Найти раздачи» AND the ordinary search in «Добавить»): a «Фильтры · N» chip opens
  a sheet; active filters show as chips under the field; «Сбросить», «Показать N раздач». Groups, all parsed from the
  torrent title (plus size/seeds fields), OR within a group, AND between groups:
  - Качество: 720p / 1080p / 4K (today's «1080p / 4K» chips move here), HDR / Dolby Vision.
  - Источник: WEB-DL / BDRip / Remux; «Скрыть экранки» (CAMRip, TS, TC, TeleSync).
  - Размер, ГБ: от / до.
  - Сиды, не меньше: любые / 1 / 5 / 20.
  - Озвучка: Дубляж / Многоголосый / Оригинал; «Рус. субтитры».
  - Сериалы (only when the query is a series or a title has season marks): season N (from the card's season, else
    the seasons found in titles); «Только полный сезон» (no «Серии: 1-6 из 10» style partial releases).
  Titles that say nothing about a group pass that group's filter except «Скрыть экранки» and «Только полный сезон»,
  which only drop titles that match their marks. Filters are remembered per device (`tsp.searchFilters`) and apply
  to subscriptions created from the search (their `quality` takes the quality group).
  Mockup: artboard 8 «Фильтры раздач».
- «Каталог недоступен» state when TMDB does not answer (network, no key, blocked): text with the hint about the TMDB
  mirror in TorrServer settings, «Повторить»; «Мои» stays usable.
- TV fix shipped in the same beta: pointer/wheel scrolling inside an open dialog never scrolls the screen behind it
  (`src/ui/wheel.ts`): when the pointer is over a dialog (or any dialog is open), the scroll target is searched only
  inside that dialog; at its edge nothing scrolls and the event is consumed.

- Delete from the phone «Каталог» («Мои»): long press on a torrent opens a menu (Открыть / Смотреть на ТВ / Переименовать / Выбрать / Удалить); «Выбрать» starts a selection mode to delete several torrents at once with one confirmation; system «Назад» leaves the mode.

- «Нет аккаунта?»: on the phone login screens a link to the site's registration page (rutracker, Kinozal on the active mirror, rustorka), on the TV login dialog a QR code to it, FAQ items «Где взять аккаунт…» and «Ключ TMDB для «Обзора»», and a «Как получить ключ» button in the «Обзор» no-key state.

- «Лучшее качество»: monitoring reports a release in better quality — for subscriptions with «Только лучшее качество» and for every film of the library (once a day per film); notification «Вышло в лучшем качестве» with «Заменить», a section in «Новое», switches in «Мониторинг», the subscription sheet, «Хочу посмотреть» and the film card. See «Лучшее качество» below.

- «Источники поиска» on the phone: one list of the built-in sites, «Войти» / «Выйти» on the row of every site with a login (rutracker, Kinozal, rustorka, NNM-Club), a short hint under a site Cloudflare stopped and one general hint at the bottom; NNM-Club gets the browser login of Kinozal and rustorka. See «Источники поиска: вход и Cloudflare» below.

Out (later): TV «Обзор»; genres, «Похожее», trending; trailers; person pages; user ratings; Seerr/Radarr/Sonarr.

## TMDB access

- Config: the active TorrServer's `/tmdb/settings` (`TmdbConfig`: `APIKey`, `APIURL`, `ImageURL`, `ImageURLRu`), as the
  poster search already does (`src/lib/posterSearch.ts`). Its API mirror and the Russian image mirror
  (`imagetmdb.com` by default) are used as is.
- Fallback: when the server has no key, OMP's own TMDB v3 key built into the app (`TMDB_FALLBACK_KEY`, from a TMDB
  account the owner registers; until it is set the constant is empty and «Обзор» shows «Каталог недоступен» with the
  hint to add a key in TorrServer). The key is not a secret in the TMDB sense (app keys ship in clients), but it is
  never logged.
- Requests go through the native http on Android (no CORS), `language=ru-RU` (or `en-US` when the app is in English), `region=RU`, `include_image_language=
  ru,null,en`. Endpoints: `discover/movie` (release type digital 4, `release_date.lte` today, `sort_by=
  primary_release_date.desc`, `vote_count.gte=20`), `tv/on_the_air`, `search/multi`, `movie/{id}` and `tv/{id}` with
  `append_to_response=credits`.
- Cache: in memory per session plus `tsp.tmdbCache` in storage for lists (15 min) and cards (24 h), capped at 200
  entries; no personal data.
- Attribution: «Данные: TMDB» line at the bottom of «Обзор» and in «О приложении» (TMDB terms).

## Architecture

- `src/catalog/tmdb.ts` — pure: URL builders, response sanitizers (`sanitizeTitle`, `sanitizeCard`, `sanitizeSeasons`),
  query rules (`torrentQuery(title, season?)`), image URLs. Chromium 53 rules (shared code). Unit-tested with fixtures.
- `src/catalog/client.ts` — `createTmdbClient(cfg, http)` → `novelties(kind, page)`, `search(q, page)`, `card(kind, id)`;
  cache; errors mapped to `CatalogError` codes `offline | nokey | blocked | bad`.
- `src/sources/filters.ts` — pure: `parseRelease(title)` → `{res, hdr, source, cam, dub, mvo, original, rusSubs,
  seasons, episodes:{from,to,of}}` (Russian and English tracker conventions), `applyFilters(list, f)`,
  `sanitizeFilters`. Replaces `filterQuality` in `src/sources/view.ts`. Shared with the TV search later.
- `src/catalog/library.ts` — matches TMDB titles to library torrents (normalized title + year from `titleCore`, and
  the TMDB id when a torrent's poster came from TMDB) for the «В медиатеке» badges.
- Phone UI under `mobile/src/screens/catalog/`: `Discover.tsx` (feed + chips + grid), `CatalogSearch.tsx`,
  `TitleCard.tsx` (film and series), `WantSheet.tsx`; the segmented switch in `Library.tsx`. Routes: `{name:'title',
  kind, id}` for the card (Back returns to «Обзор» at its scroll position); «Найти раздачи» navigates to
  `{name:'add', query, run:true}` (new optional fields on the existing route).
- Monitoring reuse: `addSubscription({query, quality, sources:null, notify:true})`; `sameQuery` decides «Слежу».

## Лучшее качество

Monitoring tells the user when a release in BETTER quality appears: (a) for subscriptions with «Только лучшее качество»;
(b) for every film of the library. Series are not part of it: the new-episodes check covers them.

- Order (`src/monitor/quality.ts`, from `parseRelease`): resolution 720 < 1080 < 2160, then the source at the same
  resolution: camrip/TS < unknown < WEB-DL/WEBRip < BDRip/BluRay/HDRip < Remux (a non-camrip beats a camrip of the
  same resolution). `qualityRank(title)` = resolution step × 10 + source step (0…34). `isBetter(candidate, have)`: both
  resolutions known → the higher one, then the better source; both unknown (0) → the source only; one side unknown → a
  known resolution wins only over an unknown-resolution camrip (and only when it is no camrip itself), an
  unknown-resolution candidate never beats a known one. Labels for the user: «1080p WEB-DL», «4K Remux», «CAMRip»
  (`qualityLabel`, `displayBadge`).
- Library films (`src/monitor/better.ts`): category «Фильмы», or an empty category guessed as a film
  (`guessCategory`, as `isWatchedSeries` does for series); not switched off by `omp.q: false` in the torrent journal
  (sibling of `omp.w`, «Следить за качеством» in the film card). Query «<название> <год>» (`posterQuery` + `yearOf`);
  a candidate has the same name (any `/` variant, `seriesNames`), the year ±1 (required when the library title has
  one), is not a series and `isBetter` than the library title; the best is the highest rank, then the most seeds.
  Each film is searched at most once per 24 h (stamps `tsp.betterChecked`, pruned to the library; a run in which no
  source answered does not use up the day). Findings: `subId: 'better'`, key `<hash>:<rank>`, `better: { torrentHash,
  torrentTitle, have, got }`; one notification per new best rank (a rank at or below one already reported for the
  film is silent); one card per film (a higher rank replaces it).
- Subscriptions: optional `better?: boolean`. When on, of a check's new results only the best one is reported, and
  only when its rank is higher than the best rank reported before for the subscription. That rank is kept as `b` in
  the subscription's record in `tsp.subsSeen` (not on the subscription): the background page already writes that
  record, and it is forgotten together with the seen results when the query or the filters change or the subscription
  is deleted. Switch «Только лучшее качество»: in the subscription sheet (default off) and in «Хочу посмотреть»
  (default on).
- Settings: «Мониторинг» → «Лучшее качество фильмов» (default on), next to «Следить за новыми сериями».
- Phone: the background run checks the films after the new episodes (same time margin; the longest-unchecked film
  first), Android channel «Лучшее качество» (`omp-better`), notification «Вышло в лучшем качестве» /
  «<фильм> · <got> · у вас <have>» with the button «Заменить» (the existing replace: history, skip settings and
  category move to the new torrent, the old one is removed). «Новое» → «Подписки»: section «Лучшее качество» with
  cards «4K WEB-DL · у вас 1080p WEB-DL», «Заменить…» (the replace sheet, «Другая раздача» from the same search) and
  «Скрыть». Film card: switch «Следить за качеством».

## Источники поиска: вход и Cloudflare

Bugs seen on the device: the yellow Cloudflare hint under a row overlapped a two-line error note (its negative top
margin), the same long hint stood under the row and at the bottom of the screen, and under NNM-Club it said «Для Kinozal
и rustorka включите обход…».

- One list: the group «Сайты за Cloudflare» goes away on the phone; every built-in site is in «Встроенные · на
  телефоне» (the TV keeps its own group). Every site with a login (`Source.login`: rutracker, Kinozal, rustorka,
  NNM-Club) has «Войти» / «Выйти» on its row like rutracker today; «Войти» opens the same sign-in sheet (password and
  «Войти через браузер»). Finishing a BROWSER login on the phone (the sheet or the site screen) turns the site's
  «Обходить проверку Cloudflare» on; a password login leaves the switch alone. The › stays on the rows of the sites
  behind Cloudflare and opens the site screen for the extras (password login, «Передать вход на телевизор», the bypass
  switch, turning it off).
- Notes: a site behind Cloudflare adds a muted «за Cloudflare» to its note while the note is not an error («за
  Cloudflare», «нужен вход · за Cloudflare», «вход выполнен в браузере · за Cloudflare»). A site with an optional login
  (NNM-Club) never says «нужен вход»; «Выйти» there clears its state instead.
- Hints: under a built-in site whose last search hit Cloudflare a SHORT hint about that site only — a site with a
  browser login: «Войдите через браузер — кнопка «Войти»» (signed in already: «Войдите через браузер заново — «Выйти»,
  затем «Войти»»); any other site: «Подключите <сайт> через Jackett, Prowlarr или FlareSolverr» and a «Как» link to the
  FAQ item `jackett`. Exactly one general hint at the bottom of the screen; its text (`sources.jackettHint`, also used
  by the search results and the sign-in sheet) names no site. Layout: the row and its hint sit in a column wrapper, the
  hint has no negative margin and the row never shrinks.
- NNM-Club: `cloudflare: true`, its host through the mirrors helper (one host, nnmclub.to), the bypass switch and the visible check like
  Kinozal; the search and the «Новое» feed stay open to guests (no `needsLogin`, on by default; the feed never uses the
  bypass, it runs in the background). An optional login through `createSiteLogin`: the phpBB 2 form
  (`forum/login.php`, `username`, `password`, `autologin`, `redirect`, `login`), signed in = the header's logout link
  `login.php?logout`, «Войти через браузер» opens `forum/login.php` and checks `forum/index.php`. Its login and browser
  session travel to the Android TV (`LOGIN_SITES`, `SESSION_SITES`, Kotlin `SourcesProtocol.SESSION_HOSTS` nnmclub.to),
  «Нет аккаунта?» links to `https://nnmclub.to/forum/profile.php?mode=register`. The TV shows «Войти» / «Выйти» on the
  NNM-Club row too («Войти на телефоне» works through the generic `tvLoginSource`). Not checked with a real account:
  the form fields, the logout marker and the session cookie names are confirmed on a device (the browser check uses no
  cookie names: phpBB guests and members share them).

## Errors and edge cases

- No active server: «Обзор» still works with the fallback key; «В медиатеке» badges are skipped.
- TMDB slow: skeleton posters; 15 s timeout per request; one retry on the next scroll.
- Title without a Russian name: the original title; query uses the Russian title when TMDB gives one, else original.
- Series card while a subscription exists: «Слежу за серией» opens it in «Новое».
- Offline mid-scroll: the loaded grid stays, a «Повторить» row at its end.
