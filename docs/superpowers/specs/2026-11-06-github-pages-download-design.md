# Страница загрузки OMP для GitHub Pages

## Цель

Сделать небольшую русскоязычную страницу по адресу `https://spacesarmat.github.io/omp/`: прямые ссылки на стабильные Android APK и webOS IPK, отдельный раздел беты, основной сайт, GitHub и инструкции.

Сейчас `gh-pages` содержит только update-фиды и Homebrew-файлы. Корневая страница возвращает 404, потому что `index.html` отсутствует.

## Подходы

1. Выбран: статические HTML, CSS и небольшой JavaScript без зависимостей. Страница читает существующие одноименные update-фиды и подставляет актуальные версии и прямые ссылки. Публикация из `main` отдельным workflow с сохранением фидов.
2. Отклонен: только постоянные ссылки на страницы релизов без JavaScript. Так проще, но пользователь должен отдельно выбирать версионированный APK или IPK.
3. Отклонен: redirect на `omp-player.online`. Он не дает отдельной страницы загрузки.

## Реализация

- `ops/pages/index.html`: семантическая страница с двумя разделами загрузки и резервными ссылками на страницы релизов.
- `ops/pages/download.js`: ES module без зависимостей. Читает `update-android.json`, `update.json`, `update-android-beta.json`, `update-beta.json`. Подставляет версии, universal APK, arm64, armv7 и IPK. Ошибка загрузки фида оставляет резервные ссылки без изменений.
- Стили встроены в HTML: системные шрифты, адаптивные карточки, заметный keyboard focus, `meta name="text-scale" content="scale"`, относительные размеры и `clamp()`. Внешние шрифты, аналитика и сторонние скрипты не используются.
- `.github/workflows/pages.yml`: публикация после изменения `ops/pages/**` в `main` и вручную. Workflow копирует только файлы страницы в клон `gh-pages`, не удаляет JSON и Homebrew-файлы и делает push без force.
- Общий `concurrency` для `pages.yml` и `release.yml` не допускает одновременной записи в `gh-pages`.

## Проверки

- Unit-тесты обновления ссылок и версий по тестовым фидам, включая arm64, armv7 и beta.
- Проверка сохранения резервных ссылок при ошибке fetch.
- Локальный HTTP-просмотр страницы на узком и широком экране, проверка работы без JavaScript.
- Стандартные `npm test`, `npm run build` и CI pull request.
- После merge: успешный `pages.yml`, HTTP 200 на странице и проверка сохранения всех ранее существовавших файлов `gh-pages`.

## Границы

- Не переносится полный `ops/vps/site`: его маршруты зависят от Caddy.
- Не добавляются английская версия, аналитика, custom domain и новые зависимости.
- Изменения проходят через PR. Публикация происходит только после разрешения на merge и успешного workflow.
