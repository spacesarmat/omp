# Страница загрузки OMP для GitHub Pages

## Цель

Сделать небольшие русскую и английскую страницы по адресам `https://spacesarmat.github.io/omp/` и `https://spacesarmat.github.io/omp/en/`: прямые ссылки на стабильные Android APK и webOS IPK, отдельный раздел беты, основной сайт, GitHub и инструкции. Добавить заметный переключатель языка.

Сейчас `gh-pages` содержит только update-фиды и Homebrew-файлы. Корневая страница возвращает 404, потому что `index.html` отсутствует.

## Подходы

1. Выбран: статические HTML, CSS и небольшой JavaScript без зависимостей. Страницы читают существующие одноименные update-фиды и подставляют актуальные версии и прямые ссылки. Публикация из `main` отдельным workflow с сохранением фидов.
2. Отклонен: только постоянные ссылки на страницы релизов без JavaScript. Так проще, но пользователь должен отдельно выбирать версионированный APK или IPK.
3. Отклонен: redirect на `omp-player.online`. Он не дает отдельной страницы загрузки.

## Реализация

- `ops/pages/index.html`: русская семантическая страница с двумя разделами загрузки и резервными ссылками на страницы релизов.
- `ops/pages/en/index.html`: английская версия с теми же возможностями. Обе страницы имеют `lang`, переключатель языка и ссылки `hreflang`.
- `ops/pages/download.js`: общий ES module без зависимостей. Читает `update-android.json`, `update.json`, `update-android-beta.json`, `update-beta.json` относительно корня GitHub Pages. Подставляет версии, universal APK, arm64, armv7 и IPK. Ошибка загрузки фида оставляет резервные ссылки без изменений.
- Стили встроены в HTML: системные шрифты, адаптивные карточки, заметный keyboard focus, `meta name="text-scale" content="scale"`, относительные размеры и `clamp()`. Внешние шрифты, аналитика и сторонние скрипты не используются.
- `.github/workflows/pages.yml`: публикация после изменения `ops/pages/**` в `main` и вручную. Workflow копирует только файлы страниц в клон `gh-pages`, не удаляет JSON и Homebrew-файлы и делает push без force.
- `scripts/git-push-retry.mjs`: обычный push без force с rebase и повторными попытками при одновременной записи. Он сохраняет каждый page и release commit и не вытесняет ожидающие запуски, как общая `concurrency`-группа.
- `pages.yml` дополнительно запрашивает Pages build через GitHub API, чтобы публикация не зависела от автоматического запуска по push.

## Проверки

- Unit-тесты обновления ссылок и версий по тестовым фидам, включая arm64, armv7 и beta.
- Проверка сохранения резервных ссылок при ошибке fetch.
- Проверка русского и английского текстов, `lang`, `hreflang` и переключателя языка.
- Локальный HTTP-просмотр обеих страниц на узком и широком экране, проверка работы без JavaScript.
- Стандартные `npm test`, `npm run build` и CI pull request.
- После merge: успешный `pages.yml`, HTTP 200 на обеих страницах и проверка сохранения всех ранее существовавших файлов `gh-pages`.

## Границы

- Не переносится полный `ops/vps/site`: его маршруты зависят от Caddy.
- Не добавляются аналитика, custom domain и новые зависимости.
- Изменения проходят через PR. Публикация происходит только после разрешения на merge и успешного workflow.
