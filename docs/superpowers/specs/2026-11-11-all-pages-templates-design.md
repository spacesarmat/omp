# Редактирование всех desktop-страниц и шаблонов OMP

## Назначение

Убрать искусственное ограничение `preview` для существующих desktop-маршрутов и дать редактору доступ ко всем страницам и шаблонам, которые реально существуют в текущем desktop preview.

## Текущее состояние

В `DESKTOP_ROUTES` зарегистрированы `library`, `news`, `search`, `remote`, `settings`, `connect`. Только `settings` имеет уровень `logic`, остальные ошибочно ограничены `preview`. `connect` скрыт из `TargetBar`. Каталог содержит четыре элемента, а `server-card` и legacy-страницы не подключены к инспектору.

## Цели этого этапа

- Все шесть desktop-маршрутов доступны в списке страниц и в `TargetBar`.
- Все шесть маршрутов поддерживают тему; `settings` дополнительно сохраняет логику.
- Общие шаблоны `sidebar`, `sidebar-item` и `content` редактируются на каждой странице.
- `server-card` и `settings-continue` доступны на настройках.
- Каждая legacy-страница имеет шаблон `legacy-page`, который применяет существующие OMP-токены к mobile CSS custom properties, а не только записывает их в черновик.
- Панель слоёв показывает страницы и реально доступные на выбранной странице шаблоны. При смене страницы выбор сбрасывается на `content`.

## Ограничение результата

Этот этап не создаёт preview-адаптеры для Android phone, Android TV и LG webOS и не утверждает, что они уже редактируются. Для полного требования по всем платформам проекта нужен следующий самостоятельный этап с отдельными preview, реестрами экранов и адаптерами токенов. Настоящий этап завершает все desktop-страницы и шаблоны, не блокируя их из-за отсутствующих платформ.

## Не входит

- Произвольный CSS или JavaScript в документах темы.
- Изменение бизнес-логики legacy-экранов.
- Новые библиотеки и новый формат документа.
- Изменение существующих чужих исправлений автосохранения.

## Подходы

1. Выбрано: реестровое включение desktop-маршрутов и адаптер `legacy-page`. Сохраняет текущую архитектуру и даёт реальные изменения в preview через существующие токены.
2. Отклонено: разрешить произвольные CSS-селекторы и текст CSS. Это дало бы видимость полного редактирования ценой хрупких и небезопасных документов.
3. Отклонено как отдельный большой этап: одновременные phone/TV preview-адаптеры. Они требуют другой маршрутизации, fixture и проверки платформенных ограничений.

## Реализация

- `DESKTOP_SCREEN_SUPPORT`: `settings: logic`, все остальные маршруты: `theme`.
- `TargetBar` использует полный `DESKTOP_ROUTES`, включая неменюшный `connect`.
- `LayersPanel` получает `onNavigate`, показывает все страницы и фильтрует шаблоны по текущему маршруту.
- `DESIGN_ELEMENTS` пополняется `server-card` и `legacy-page`; используются только уже валидные токены.
- `PreviewRoute` помечает каждый legacy wrapper стабильными design ID и override attrs.
- `shell.css` связывает `--bg`, `--panel`, `--panel-2`, `--accent`, `--text`, `--muted` и размеры с OMP-токенами внутри `.desktop-legacy`.
- `DesktopSettingsScreen` подключает `server-card` к `designOverrideAttrs`.

## Решения после проверки исполнителя

Это решения исполнителя, а не новые требования Andy:

- `--panel-2` вычисляется через `color-mix(in srgb, var(--omp-color-panel) 92%, var(--omp-color-text))`. Дополнительный токен и изменение схемы не нужны, вторичная поверхность реагирует на редактирование обоих базовых цветов.
- `--omp-size-space` задаёт padding `.m-screen` и высоту кнопки через `--m-btn-h: calc(var(--omp-size-space) * 3.25)`. `--omp-size-font` задаёт размер текста `.m-btn` и `.m-input`. `--omp-size-radius` применяется к общим `.m-btn`, `.m-input`, `.m-server`, `.m-card`, `.m-tv` и `.m-panel`. Остальные специализированные размеры mobile UI не растягиваются искусственно.
- Адаптер находится в `desktop/src/shell/shell.css`, который импортирует общий `DesktopShell`, а не в CSS редактора. Поэтому одно правило работает в preview и в реальном desktop shell; экспорт продолжает генерировать только проверенные токены и overrides.
- При переходе на любой маршрут с поддержкой ниже `logic` редактор принудительно возвращается в `design`, чтобы не показывать логику `settings-continue` на других страницах.

## Проверка

- Тесты уровня поддержки всех маршрутов и присутствия `connect` в редакторе.
- Тесты страниц и шаблонов в `LayersPanel`, сброса выбора и редактирования legacy-страницы.
- Тесты применения override attrs к `server-card` и legacy wrapper.
- `npm run test:editor`, `npx tsc --noEmit`, `npm run build:editor`.
- Браузер: перебрать все шесть страниц, изменить `legacy-page` и `server-card`, проверить результат и вернуть тестовые значения.
