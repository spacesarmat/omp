# v0.6 «Обновления и Homebrew» — дизайн

Дата: 2026-10-02 · Основа: v0.5.0 (`main` @ 7becc61) · Ветка `feat/v0.6-updates`

## Решения пользователя

- **Публикация.** Используем оба пути:
  - PR в официальный каталог `webosbrew/apps-repo`;
  - собственный репозиторий OMP для Homebrew Channel. Его можно добавить в Homebrew Channel одной кнопкой прямо из OMP.
- **Обновление.** Окно появляется при запуске. Кнопка «Обновить» ведёт на экран со всеми способами, пользователь выбирает сам.
- **Параметры запуска.** Делаем базовые уже в этой версии.

## Факты о Homebrew Channel (проверено по исходникам webosbrew)

- **Сервис установки.** `luna://org.webosbrew.hbchannel.service/install` принимает `{ ipkUrl, ipkHash, subscribe }`. С `subscribe` ответы приходят несколько раз:
  - `{ statusText, progress? }` по ходу работы;
  - `{ finished: true }` в конце;
  - ошибка в виде `returnValue:false` и `errorText`.

  Другим приложениям сервис доступен только на ТВ с root.
- **Проверка root.** `checkRoot` отвечает `{ returnValue: runningAsRoot }`. Значит, на ТВ без root вызов возвращает `false` и приходит как ошибка.
- **Открытие на экране добавления репозитория.** Приложение `org.webosbrew.hbchannel` можно запустить с параметрами `{ launchMode: 'addRepository', url }`. Оно откроется сразу на экране «Добавить репозиторий» с подставленной ссылкой.
- **Формат репозитория.** `{ paging?, packages: [{ id, title, iconUri, manifestUrl, manifest, pool, shortDescription }] }`.
- **Формат манифеста.** `{ id, version, type, title, appDescription, iconUri, sourceUrl, rootRequired, ipkUrl, ipkHash: { sha256 }, ipkSize? }`.
- **Официальный каталог.** Новое приложение добавляется файлом `packages/<id>.yml` с полями `title`, `iconUri`, `manifestUrl`, `category`, `pool`, `description`. Правила каталога: NO AI SLOP, NO PIRACY.

## 1. Источник обновлений

- **Где лежат файлы.** Релизный workflow публикует в ветку `gh-pages` три файла:
  - `update.json` — для OMP;
  - `apps.json` — репозиторий для Homebrew Channel;
  - `com.spacesarmat.torrplayer.manifest.json`.

  Все три доступны по адресу `https://raw.githubusercontent.com/spacesarmat/omp/gh-pages/<файл>`. Этот хост отдаёт `Access-Control-Allow-Origin: *` и не ограничивает число запросов.
- **Формат `update.json`.** `{ version, ipkUrl, ipkHash, ipkSize, notes: string[], releaseUrl }`.
  - `notes` — пункты из `CHANGELOG.md` для этой версии.
  - Ссылки должны быть https, `ipkHash` — 64 шестнадцатеричных символа.
  - Если файл не проходит проверку, считаем, что обновления нет.
- **Сравнение версий.** Числовое, по частям через точку; ведущая `v` игнорируется.

## 2. Проверка при запуске

- **Настройка.** `updateCheck: boolean` в `AppSettings`, по умолчанию `true`. В Настройках называется «Проверять обновления при запуске».
- **Состояние.** Хранится в `tsp.update` и состоит из `lastCheck` (мс) и `skipped` (версия или отсутствует).
- **Когда проверяем.**
  - Фоновая проверка запускается через 3 с после старта приложения, если настройка включена и с последней проверки прошло не меньше 6 часов.
  - Ручная проверка из Настроек игнорирует и интервал, и настройку.
  - Ошибки сети при проверке молчаливые. При ручной проверке показывается тост: «Не удалось проверить обновления», «У вас последняя версия» или открывается окно.
- **Окно «Доступна версия X».** Показывается, если версия новее `APP_VERSION` и не совпадает со `skipped`.
  - Содержимое: заголовок «Доступна версия 0.6.1», до 8 пунктов изменений, строка «Сейчас установлена 0.6.0».
  - Кнопки:
    - «Обновить» — переход на экран «Обновление»;
    - «Позже» — закрыть до следующего запуска;
    - «Пропустить эту версию» — записать `skipped`.
  - «Назад» работает как «Позже».
  - Окно модальное, приоритет клавиш 70. Над плеером оно не открывается: если пользователь в плеере, окно ждёт выхода из него.

## 3. Экран «Обновление» (маршрут `update`)

Заголовок «Обновление OMP», под ним строка «Установлена X → доступна Y». Если доступной версии нет, только «Установлена X» и кнопка «Проверить обновления».

Ниже три блока, каждый со своим заголовком.

### 3.1. Установить сейчас

- **Когда виден.** Только если `checkRoot` ответил успешно.
- **Кнопка «Установить».** Вызывает `install` с подпиской.
- **Ход установки.**
  - Строка статуса по-русски: «Скачивание… N%», «Проверка…», «Установка…».
  - Полоса прогресса для скачивания.
  - По `finished` выводится «Готово. OMP перезапустится».
- **Ошибка.** Показывается текст ошибки и кнопка «Повторить».
- **Без root.** Блок не показывается вовсе.

### 3.2. Через Homebrew Channel

- **Как определяем установку Homebrew Channel.** Вызов `luna://com.webos.applicationManager/getAppInfo` с `{ id: 'org.webosbrew.hbchannel' }`. Если вызов недоступен (ошибка Luna), считаем, что Homebrew Channel может быть установлен, и показываем блок с оговоркой.
- **Кнопки.**
  - «Открыть Homebrew Channel» — запуск без параметров.
  - «Добавить репозиторий OMP» — запуск с `{ launchMode: 'addRepository', url: <apps.json> }`.
- **Инструкция.** «Найдите OMP в списке и нажмите «Обновить». Если OMP нет в списке — добавьте репозиторий OMP».
- **Если Homebrew Channel не установлен.** Текст «Homebrew Channel не установлен» и QR-код на `https://www.webosbrew.org/`.

### 3.3. С компьютера

- QR-код на страницу релиза (`releaseUrl`, иначе `https://github.com/spacesarmat/omp/releases/latest`).
- Шаги:
  1. Скачайте файл .ipk со страницы релиза.
  2. Установите его через webOS Dev Manager (Windows/macOS/Linux) или командой `ares-install`.
  3. Настройки и сохранённые серверы не пропадут.

## 4. Настройки → «О приложении»

Раздел ставится последним.
- Строка «Версия X», рядом пометка «доступна Y», если обновление найдено.
- Кнопка «Проверить обновления».
- Переключатель «Проверять обновления при запуске».
- Кнопка «Добавить репозиторий OMP в Homebrew Channel».
- Кнопка «Обновление», ведущая на экран из §3.

## 5. Параметры запуска

**Откуда берутся.**
- При старте — из `window.PalmSystem.launchParams` (JSON-строка).
- При повторном запуске уже открытого приложения — из события `webOSRelaunch` на `document`; параметры снова читаются из `PalmSystem.launchParams`.
- В `appinfo.json` добавляется `"handlesRelaunch": true`.

**Разбор (`parseLaunchParams`).** Принимает строку или объект. Первым срабатывает первый подходящий ключ:

| Параметры | Действие | Проверка |
|---|---|---|
| `{ server: адрес }` | addServer, выбор сервера, переход в библиотеку | непустая строка |
| `{ magnet: ссылка }` | добавить раздачу на сервер, открыть её | ссылка начинается с `magnet:` |
| `{ torrent: hash }` | открыть раздачу | 40 шестнадцатеричных символов |
| `{ play: url, title? }` | сразу воспроизвести | только `http://` или `https://` |

Если подошёл ключ, но значение неверное, — тост «Некорректные параметры запуска». Пустые и посторонние параметры игнорируются молча.

**Совмещение с `server`.** Ключ `server` может прийти вместе с `magnet`, `torrent` или `play`: сначала выбирается сервер, затем выполняется второе действие.

**Если сервера нет.** Для `torrent` и `magnet` без активного сервера — тост «Сначала подключитесь к серверу» и экран входа.

**Документация.** Примеры для `ares-launch` и Luna описываются в README.

## 6. Публикация

- **`scripts/hb-manifest.mjs`.** Запускается в CI после упаковки. Принимает тег и путь к .ipk, считает SHA-256 и размер, а затем пишет в `build/hb/`:
  - манифест (ipkUrl — `https://github.com/spacesarmat/omp/releases/download/<тег>/<имя.ipk>`);
  - `apps.json` с одним пакетом и встроенным манифестом;
  - `update.json` с `notes` из `CHANGELOG.md` и `releaseUrl` на страницу тега.

  Чистая функция сборки этих объектов вынесена в `scripts/hb-lib.mjs` и покрыта тестом.
- **`release.yml`.**
  - Прикладывает манифест к релизу как файл.
  - Публикует `build/hb/` в ветку `gh-pages`: каждый раз заново, одним коммитом, через `git push --force` с `GITHUB_TOKEN`.
- **`CHANGELOG.md`.** Разделы вида `## 0.6.0` со списками пунктов. Эти пункты попадают в `notes` и в окно обновления.
- **`docs/homebrew/com.spacesarmat.torrplayer.yml`.** Файл для PR в официальный каталог:
  - `category: multimedia`, `pool: main`;
  - `manifestUrl` — манифест из `releases/latest/download`;
  - нейтральное описание на английском: клиент для собственного TorrServer пользователя, без встроенных трекеров;
  - скриншоты из `docs/screenshots`.

  Сам PR отправляется вручную после релиза и только после того, как пользователь одобрит текст.
- **README.** Новые разделы:
  - «Установка через Homebrew Channel»: официальный каталог и репозиторий OMP по адресу `apps.json`;
  - «Обновление»;
  - «Параметры запуска».
- **Версия.** 0.6.0.

## Ограничения

- Chromium 53: без наследования от Error, без AbortController, без CSS grid / flex gap / inset, регулярные выражения без `u` и lookbehind.
- Тексты только на русском.
- localStorage — только через `loadJson` и санитайзер.

## Тестирование

- **Vitest:**
  - сравнение версий;
  - санитайзер `update.json`;
  - `parseLaunchParams` — все ветки;
  - `store/updates` — интервал, `skipped`, ручная проверка, ошибки сети; через mockFetch;
  - `hbchannel` — через подменённый `PalmServiceBridge`: успех, отказ, подписка с несколькими ответами;
  - сборка манифеста, репозитория и `update.json`;
  - отрисовка QR;
  - экран «Обновление»: без root, с root, без Homebrew Channel.
- **Вручную в браузере:** окно при запуске (подменённый `update.json`), экран «Обновление», Настройки.
- **CI:** `release.yml` проверяется на следующем теге.
