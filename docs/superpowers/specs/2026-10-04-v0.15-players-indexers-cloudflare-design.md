# v0.15 «Плеер VLC, Jackett и сайты за Cloudflare» — дизайн

Дата: 2026-10-04 · Основа: v0.14.1 (`main`) · Ветка `feat/v0.15-players-indexers`
Макеты: будут на холсте v0.15 (ссылка добавится после одобрения).

## Решения пользователя

- Плеер на Android TV: **FFmpeg-декодер** для встроенного плеера и **libVLC вторым движком**; выбор **«Авто» + ручной**.
- Jackett/Prowlarr: **оба способа** — прямое подключение (поиск по Torznab, состояние трекеров), иначе как сейчас через TorrServer; автопоиск в сети.
- FlareSolverr: инструкция + проверка в OMP; **запасной путь** для встроенных сайтов, если встроенный обход не прошёл.
- Обход Cloudflare встроенным браузером — **на телефоне и Android TV**; включается для каждого сайта отдельно.
- Вернуть сайты: **Kinozal, rustorka, seedoff, labtor, BitRu** (каждый включается отдельно; вход — как у rutracker).
- В Telegram-канал публикуются **все сборки выпуска** файлами (APK под архитектуры и ipk).
- Номер версии — **0.15**; Samsung Tizen переезжает в 0.16.

## 1. Плеер на Android TV

- **Движок плеера** (`PlayerEngine` в Kotlin): общий интерфейс (открыть, play/pause, перемотка, дорожки аудио/субтитров, позиция/длительность, события «готов / ошибка / конец»). Два движка: Media3 (как сейчас) и libVLC. Весь интерфейс плеера — кнопки, главы, «Пропустить заставку/титры», ручные отметки, карточка «Поддержать», отсчёт «Следующая серия», запоминание позиции — работает поверх интерфейса, одинаково для обоих.
- **FFmpeg для Media3**: готовая сборка декодера с совместимой лицензией (кандидат — `media3-ffmpeg-decoder` от Jellyfin; проверить, что FFmpeg собран без GPL-частей). Если подходящей нет — собрать из исходников Media3 с LGPL-конфигурацией в CI. Даёт DTS, AC3/E-AC3, TrueHD, если приставка не умеет аппаратно. Первая задача плана — проверка лицензии и размера.
- **libVLC**: `org.videolan.android:libvlc-all` (LGPL-2.1), только `arm64-v8a` и `armeabi-v7a`. Субтитры ASS/SSA со стилями, почти все контейнеры и кодеки.
- **«Авто»** (по умолчанию): играет Media3; переключение на VLC с той же позиции, если (а) Media3 сообщил об ошибке до первого кадра (неподдерживаемый формат/декодер), или (б) по данным ffprobe в файле выбраны/есть субтитры ASS/SSA. Ручной выбор: настройки ТВ «Плеер: Авто / Встроенный / VLC» и в меню плеера «Сменить плеер» (запоминается для этой раздачи).
- **Сборки**: APK разделяется по архитектурам — `OMP-x.y.z-arm64.apk`, `OMP-x.y.z-armv7.apk` (и универсальный `OMP-x.y.z.apk` остаётся на GitHub для ссылок и ленты обновлений, если он не больше лимитов GitHub; лента обновлений Android выбирает APK под архитектуру устройства). Помощник установки и «Обновить на ТВ» берут APK под архитектуру приставки.
- **Журнал ошибок**: переключение движка — запись «ВНИМАНИЕ · tv» без названия файла.

## 2. Jackett и Prowlarr

- **Новый вид источника** «Индексатор» (`kind: 'indexer'`): Jackett или Prowlarr по адресу + API-ключ. Поиск — Torznab/Newznab API (`/api/v2.0/indexers/all/results/torznab` у Jackett, `/{id}/api` или `/api/v1/search` у Prowlarr), разбор XML в общий `SourceResult`. Запросы идут через нативный HTTP (как у встроенных сайтов), на LG — не поддерживается (там остаётся поиск через TorrServer).
- **Где берутся подключения**: (1) из настроек TorrServer, если там заданы адреса Torznab и ключи; (2) поиск в домашней сети — порты 9117 (Jackett) и 9696 (Prowlarr) в подсети устройства, с таймаутами и не чаще раза в сутки без нажатия; (3) вручную. Ключи — в зашифрованном хранилище; в журнале ошибок и резервной копии их нет (в копии — только адрес и «ключ задан»).
- **Выбор пути поиска**: если есть прямое подключение — поиск через него; иначе — через TorrServer (как сейчас). Источник «Torznab (TorrServer)» скрывается, когда прямое подключение к тому же Jackett уже есть, чтобы не было дублей.
- **Состояние трекеров**: список трекеров внутри Jackett/Prowlarr с состоянием «работает / ошибка / нужен вход / Cloudflare / выключен» и временем последней проверки (Jackett — список настроенных индексаторов и результат тест-запроса; Prowlarr — `/api/v1/indexer` + `/api/v1/indexerstatus`). Экран — в «Источниках поиска» (телефон и Android TV), строка индексатора раскрывается в список трекеров.
- **Передача на ТВ**: подключения к индексаторам передаются на Android TV вместе с источниками (как в v0.14), ключи — только в зашифрованное хранилище ТВ.

## 3. Обход Cloudflare

- **Распознавание**: ответ 403/503 с признаками Cloudflare (заголовок `cf-mitigated: challenge`, `server: cloudflare` + страница «Just a moment…»/`challenge-platform`).
- **Встроенный обход** (нативно, `CloudflareSolver`): скрытый WebView с тем же User-Agent, что у нативного HTTP; загрузка страницы, ожидание cookie `cf_clearance` до 20 с; cookie переносятся в `SiteCookieJar`, запрос повторяется. Cookie хранятся до истечения и обновляются при следующей проверке.
- **Если нужна галочка** (интерактивная проверка): телефон — окно с сайтом поверх экрана («Подтвердите, что вы не робот», «Отмена»); Android TV — окно с сайтом под пульт и кнопка **«Пройти на телефоне»**: телефон по каналу пары получает адрес, проходит проверку и передаёт cookie на ТВ (тот же User-Agent на обоих устройствах; внешний IP общий через роутер).
- **Запасной путь — FlareSolverr** (если задан адрес): `POST /v1` `request.get`, из ответа берутся cookie и User-Agent; запрос повторяется с ними. В «Источниках поиска» — блок FlareSolverr: адрес (поиск в сети на порту 8191), «Проверить» (запрос к `/` → версия), состояние.
- **Включение**: у каждого сайта за Cloudflare переключатель «Обходить проверку Cloudflare» (по умолчанию выкл.) и пояснение: это может нарушать правила сайта, используйте на свой риск.
- **Журнал**: «Cloudflare: проверка пройдена / нужна галочка / не удалось» с именем сайта, без адресов и cookie.

## 4. Пять сайтов

- **Kinozal, rustorka, seedoff, labtor, BitRu** — модули в `src/sources/` по образцу существующих (поиск → список с размером, сидами, датой; ссылка на раздачу → .torrent или magnet), через обход Cloudflare из §3.
- **Вход** там, где без него нет поиска или .torrent (Kinozal, rustorka, labtor; seedoff/BitRu — проверить): как у rutracker — окно входа на телефоне и ТВ, пароль в зашифрованном хранилище, передача с телефона на ТВ, капча — сообщение «Войдите на сайте в браузере», без обхода капчи.
- **По умолчанию выключены**; в «Источниках поиска» — отдельная группа «Сайты за Cloudflare».
- Парсеры не входят в сборку для LG (как в v0.14).

## 5. Публикация в Telegram

- В канал уходят **все сборки выпуска** файлами: `OMP-x.y.z-arm64.apk`, `OMP-x.y.z-armv7.apk`, `OMP-x.y.z-webOS.ipk` — ответами на пост с изменениями и кнопками.
- Лимит обычного Bot API — 50 МБ на файл. Если какая-то сборка больше: шаг выпуска поднимает на время свой сервер Telegram Bot API (`telegram-bot-api` в Docker, лимит 2 ГБ) — нужны секреты `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`; без них большие файлы публикуются ссылкой.
- Ошибка публикации не ломает выпуск (как в 0.14.1).

## Ограничения

- ТВ-код (`src/`) — правила Chromium 53, без `@capacitor`; новые парсеры и индексаторы не входят в сборку LG.
- Без GPL-зависимостей (FFmpeg только в LGPL-сборке, libVLC — LGPL-2.1); лицензии новых библиотек — в README «Лицензия».
- Пароли сайтов, API-ключи индексаторов, cookie Cloudflare — только в зашифрованном хранилище или в памяти; никогда в журнал, localStorage, резервную копию, тесты.
- Запросы только к адресам, которые задал или нашёл пользователь (сайты, его Jackett/Prowlarr/FlareSolverr, TorrServer); никаких сторонних сервисов обхода.
- Тексты только на русском. Без строк соавторства.

## Тестирование

- Vitest: разбор Torznab/Newznab XML, выбор пути поиска (прямой / TorrServer / без дублей), состояние трекеров (Jackett/Prowlarr на фейках), автопоиск (подсеть, таймауты, частота), парсеры пяти сайтов на сохранённых страницах (выдуманные названия), окна входа и переключатели, передача подключений и cookie на ТВ (протокол), выбор движка «Авто» (ошибка до первого кадра, ASS по ffprobe), публикация в Telegram (выбор файлов, лимит 50 МБ, ссылка вместо файла).
- Kotlin: распознавание Cloudflare (заголовки/страницы), перенос cookie, FlareSolverr-клиент на фейке, `PlayerEngine` (переключение с сохранением позиции, без реального видео), выбор APK по архитектуре.
- CI: job Android проходит; размер APK каждой архитектуры выводится в журнал сборки.
- Проверка на устройствах — вопросами по очереди после выпуска.
