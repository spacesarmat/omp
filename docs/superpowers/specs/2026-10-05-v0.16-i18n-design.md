# OMP 0.16 — Russian and English (design)

Date: 2026-10-05. Ships as 0.16.0-beta.1 (the first beta through the beta channel), before «Обзор» (0.16.0-beta.2,
`docs/superpowers/specs/2026-10-05-v0.16-obzor-design.md`, whose plan moves its copy into these dictionaries).

## Goal

Every screen, message and notification of OMP in Russian or English: the phone app, OMP on LG, OMP on Android TV,
the native Android parts, «Вопросы и ответы», «Что нового», README and the GitHub release page.

## Decisions

- Named keys: `t('settings.update.title')`, dictionaries `src/i18n/ru.ts` and `src/i18n/en.ts`. The Russian dictionary is
  the source of truth for the shape; `en.ts` is typed as the same shape, so a missing or extra key fails `tsc`.
- Language setting `language: 'system' | 'ru' | 'en'` (default `'system'`) in `AppSettings`. System language: the
  first of `navigator.languages` / `navigator.language`; `ru`, `uk`, `be`, `kk` (any region) → Russian, anything
  else → English. A change applies at once (signals), no restart.
- The phone sets the TV's language: the phone sends its resolved language (`ru` | `en`) when it launches or attaches
  OMP on the TV (LG launch params, Android TV launch/attach) and in «Передать на телевизор» (Android TV transfer
  payload field `language`). The TV stores it as its `language` setting. The TV also has its own switch in its
  settings; the latest change wins.
- Telegram posts stay Russian. Tracker data is never translated (titles, tracker error pages). Patterns that parse
  tracker titles and pages (`Сезон`, `Серии`, `Дубляж`, …) stay as code, not copy.

## Architecture

- `src/i18n/ru.ts` — `export const ru = { common: {…}, library: {…}, … } as const` grouped by area (one group per
  screen family: `common`, `connect`, `library`, `torrent`, `player`, `add`, `sources`, `cloudflare`, `monitor`,
  `news`, `remote`, `tv`, `settings`, `update`, `install`, `backup`, `log`, `donate`, `errors`, `notify`, …).
  Values are strings with `{name}` placeholders, or plural objects `{ one, few, many }` (Russian).
- `src/i18n/en.ts` — `export const en: Dict = {…}` with plural objects `{ one, other }` (the `Dict` type maps every
  Russian plural object to an English one).
- `src/i18n/index.ts` — `lang` signal (`'ru' | 'en'`), `setLanguageSetting`, `resolveLanguage(setting, navLangs)`,
  `t(key, params?)`, `tp(key, n, params?)` (plural form by the language's rule: Russian one/few/many by n % 10 and
  n % 100, English one/other), `fmtDate(ms, style)`, `fmtSize(bytes)`, `fmtNumber(n)`, `fmtDuration(min)` — written
  without `Intl.PluralRules` (Chromium 53). Keys are typed: `Key` is the union of dot paths of string leaves,
  `PluralKey` of plural leaves.
- Components read `t()` in render, so the `lang` signal re-renders them on change. Module-level constants that hold
  copy become functions or are read through `t()` at use.
- Native Android: `android/.../I18n.kt` — `I18n.lang` (persisted in SharedPreferences `omp.lang`, set by a plugin
  call `setLanguage({ lang })` on start and on change) and `I18n.s(key)` with two maps. Strings that already come
  from the page (Cloudflare and browser-login dialogs, check texts) stay page-driven. Native-only copy: background
  notifications (monitoring, TV requests), install assistant progress, local TorrServer states, error messages shown
  to the user. Errors the page matches keep codes; the page matches codes, never Russian messages.
- «Вопросы и ответы»: `mobile/src/faq.ts` keeps the structure; texts move to `mobile/src/faq.ru.ts` and
  `mobile/src/faq.en.ts` keyed by question id; a test checks both have the same ids and fields.
- «Что нового»: `CHANGELOG.en.md` with the last 6 versions in English, then every new version in both files; the
  build reads the file of the language; release notes (GitHub) get an English section from `CHANGELOG.en.md`.
- `README.en.md`, linked from the top of `README.md` and back.
- TMDB («Обзор», later) asks for `language=en-US` in English.

## Guard rails

- `tests/i18n/noRussianInCode.test.ts`: scans `src/**/*.ts(x)` and `mobile/src/**/*.ts(x)` for Cyrillic inside string
  or template literals and JSX text, outside `src/i18n/`, `mobile/src/faq.ru.ts` and an explicit allowlist of
  tracker parsers (each entry with a reason). During the migration a `PENDING` list holds the files not yet moved;
  each migration task removes its files; the last task empties it.
- `tests/i18n/dicts.test.ts`: every placeholder used in a Russian string exists in its English one and vice versa;
  no empty strings; plural objects complete.
- English smoke tests: the main phone screens and the TV home, settings and player rendered with `lang = 'en'` contain
  no Cyrillic outside tracker data.
- The test setup pins Russian (`setLanguageSetting('ru')` in a Vitest setup file), so existing tests keep their
  Russian assertions.

## Migration order (plan tasks)

1. Core (`src/i18n`, setting, setup file, guard tests with the full PENDING list).
2. Language switch on phone and TV, phone → TV language (launch params, attach, transfer), native `setLanguage`.
3–10. Area by area: shared `src/lib`, `src/store`, `src/api`, `src/platform`; `src/sources` (user-facing messages
   only); `src/monitor` + `mobile/src/monitor`; TV `src/player`; TV `src/screens` + `src/ui` + `src/app.tsx`;
   `mobile/src/ui`; `mobile/src/screens` (two tasks); the rest of `mobile/src`.
11. Native Android (`I18n.kt`, notifications, install assistant, local server, errors by code).
12. «Вопросы и ответы» in English.
13. «Что нового», release notes, README in English.
14. English smoke tests, PENDING empty, version 0.16.0-beta.1, release through the beta channel.

## Testing

Each task keeps the whole suite green (Russian), adds its English cases where behaviour differs (plurals, dates),
and removes its files from PENDING. Device checks: phone, LG and Android TV in English and Russian; switching
language on the phone changes the TV's on the next launch.
