# v0.2 «Надёжность» — дизайн

Дата: 2026-10-02 · Статус: согласован · Основа: v0.1.0 (`main` @ fa7361b)

Первый из этапов развития (v0.2 надёжность → v0.3 просмотр → v0.4 библиотека → v0.5 Tizen + Android TV → v0.6 Android-пульт).

## Цели

1. Приложение не перестаёт запускаться из-за повреждённых данных в localStorage.
2. Исправлены ошибки v0.1, заметные пользователю: стирание логина/пароля сервера, смешение данных разных серверов, наложение запросов автообновления.
3. Одна точка истины для версии — `package.json`.
4. CI на GitHub: тесты, типы, сборка, упаковка `.ipk`, проверка запуска из `file://`; релиз по тегу `vX.Y.Z` с `.ipk`.
5. Исправления по итогам проверки на ТВ — по мере поступления отчётов от пользователя (вне этого плана).

## Решения

### Хранилище
- `loadJson(key, fallback, isValid?)`: при битом JSON или непрошедшей проверке возвращает `fallback` и удаляет ключ.
- Санитайзеры по типам данных: `sanitizeServers` (массив объектов с `id`/`name`/`url` строками; лишнее отбрасывается), `sanitizeSettings` (значения по умолчанию + только поля верного типа; `subSize`/`subColor` — из допустимых значений), `sanitizeProgress` (записи с конечными числами `time`/`duration`/`updated`), `sanitizeTorrents` (объекты со строковым `hash`). `tsp.activeServer` — строка или `null`.

### Данные, привязанные к серверу
- `addServer` для существующего адреса сохраняет прежние `user`/`password`, если новые не переданы (`undefined`).
- `setActiveServer(id)` при смене сервера очищает `serverViewed` и кэш библиотеки (`torrents` + `tsp.torrents`).
- `refreshTorrents` не запускает новый запрос, пока предыдущий не завершён (возвращает тот же промис).

### Версия
- Vite `define: { __APP_VERSION__ }` из `package.json`; `src/version.ts` экспортирует её.
- `scripts/package.mjs` пишет в `dist/appinfo.json` версию из `package.json`; имя `.ipk` и `scripts/tv.mjs` используют её же.

### CI и релизы
- `.github/workflows/ci.yml`: push в `main` и `feat/**`, pull_request → Node 24, `npm ci`, `npm test`, `npm run build`, `node scripts/package.mjs`, `node scripts/boot-check.mjs`, артефакт `.ipk`.
- `.github/workflows/release.yml`: push тега `v*` → те же шаги + проверка, что тег = `v` + версия из `package.json`, создание релиза GitHub с `.ipk` и SHA-256.
- `scripts/boot-check.mjs`: headless Chrome (`CHROME_PATH` или стандартные пути Windows/Linux) открывает `dist/index.html` через `file://`, ждёт рендер и требует `class="screen connect"` в DOM; доступен как `npm run check:boot`.

## Тестирование
- Vitest: `loadJson` (битый JSON, проверка, удаление ключа), все санитайзеры, `addServer` с сохранением логина, `setActiveServer` очищает данные, `refreshTorrents` без наложения, `APP_VERSION` = версия `package.json`.
- CI проверяется первым запуском на GitHub (зелёный статус PR).

## Вне рамок
Функции v0.3+ (просмотр, библиотека, платформы, пульт).
