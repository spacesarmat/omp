# Исправления аудита 0.20.10

## Цель и границы

В отдельной ветке `feat/audit-0.20.10` исправить пять подтверждённых проблем аудита без изменений в `main`: безопасность `/v1/torrent`, мобильные вкладки на 320 px, Postgres в release gate, переносимость тестового окружения и ложные срабатывания overflow-check.

Не входят: разделение бандлов, изменение масштабирования, deprecated Android API, дополнительные rate limits и рефакторинг крупных модулей.

## Подходы

- Минимальные точечные изменения с регрессионными тестами. Сохраняются существующие интерфейсы и сценарии скачивания magnet.
- Полный запрет внешних редиректов. Отклонён: Jackett и JacRed используют их для раздач.
- Пропуск POSIX-тестов на Windows. Отклонён: это скрывает проверки. Свежий checkout приводится к LF, а полный прогон документируется через Linux или WSL.

## Решения

- `/v1/torrent`: Basic-auth сохраняется только для того же origin, внешний redirect разрешён по HTTPS без учётных данных в URL. Общий таймаут 20 секунд и предел ответа 5 MiB покрывают оба запроса и чтение тела.
- Мобильный UI: вкладки получают узкую типографику на 320-374 px, инструменты календаря перестраиваются в столбец. `.m-chips` признаётся доступным горизонтальным скроллером. Проверка добавляется в package scripts и CI.
- Release: используется Postgres 17 как в CI, устанавливаются зависимости биллинга и `BILLING_TEST_REQUIRE_PG=1`.
- Windows: все текстовые файлы в новом checkout получают LF. Полный POSIX-набор запускается в Linux или WSL, это задокументировано.

## Проверка и риски

Для каждой задачи сначала запускается падающий тест. Затем выполняются focused tests, `npm test`, `npm run build`, `npm run build:mobile`, Android unit tests и debug build, Postgres-тесты, overflow-check и скриншоты 320 px. Главный риск - совместимость внешних редиректов и потеря доступа к чипам при изменении flex-раскладки.
