# v0.9 «TorrServer на телефоне» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Embed TorrServer (arm64) in the OMP Android app, start it as a foreground service from the connect screen or Settings, let the TV use it, and auto-release OMP when TorrServer updates.

**Spec:** `docs/superpowers/specs/2026-10-02-v0.9-embedded-torrserver-design.md` (binding; copy verbatim from it). Mockups: scratchpad `omp-v09/project/*.dc.html` (paths given in dispatches).

## Global Constraints

- Mobile code (`mobile/`) Android 8+ / WebView Chrome 90+; TV code (`src/`) Chromium 53 rules if touched.
- UI text Russian only, copy exactly as in the spec. localStorage keys `tsp.*` via loadJson + sanitizer.
- Server: port 8090; binary `TorrServer-android-arm64` from the tag in `torrserver.version`; packaged as `android/app/src/main/jniLibs/arm64-v8a/libtorrserver.so` (gitignored, never committed); SHA-256 must match the GitHub asset `digest`.
- Vitest: no global mocks/setup files; existing seams; run from repo root.
- Commits: Conventional, subject only. NO Co-Authored-By / co-author / AI lines.
- If `npm run android:debug` changes `android/*.gradle` only in line endings, restore them before committing.

### Task 1: Build pipeline for the embedded binary

**Files:** `torrserver.version` (content `MatriX.145.1`), `scripts/fetch-torrserver.mjs` (+ pure helpers in `scripts/torrserver-lib.mjs`), `.gitignore`, `android/app/build.gradle` (`packaging { jniLibs { useLegacyPackaging = true } }`), `package.json` (`android:sync` runs the fetch first; new script `fetch:torrserver`), `.github/workflows/release.yml` (fetch before the Android build), tests `tests/scripts/torrserverLib.test.ts`.

Behaviour: the script reads the tag, calls `https://api.github.com/repos/YouROK/TorrServer/releases/tags/<tag>` (uses `GITHUB_TOKEN` env if present), picks asset `TorrServer-android-arm64`, requires `digest` `sha256:<64 hex>`, downloads (follow redirects), verifies SHA-256, writes the .so atomically (temp + rename), skips download when an existing file already matches the digest. Clear errors in Russian or English for missing asset/digest/mismatch. Pure helpers tested: asset pick, digest parse, version file parse.

- [ ] Tests, implement, run the fetch locally, `npm run android:debug` (APK contains `lib/arm64-v8a/libtorrserver.so`; check with `unzip -l`), commit `build(android): embed the TorrServer binary`

### Task 2: Native foreground service and plugin methods

**Files:** `android/.../TorrServerService.kt`, `OmpNativePlugin.kt`, `AndroidManifest.xml`, `mobile/src/platform/native.ts`, tests `mobile/tests/native.test.ts`.

Behaviour (spec «Служба» and «Плагин»): service of type `specialUse` (manifest `<property android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE" android:value="Local TorrServer for streaming to TV"/>`), permissions listed in the spec; runs the binary with the spec flags; WifiLock + partial WakeLock while running; one restart after 3 s on unexpected exit then stopped with error; notification channel «TorrServer», text «TorrServer работает» / «<IP>:8090 · N раздач · скорость» refreshed every 5 s from `http://127.0.0.1:8090/torrents` (POST `{"action":"list"}`), actions «Остановить» (stops service) and «Открыть OMP». Plugin methods: `localServerInfo`, `startLocalServer` (requests POST_NOTIFICATIONS on Android 13+ first; resolves when `/echo` answers or rejects after 15 s), `stopLocalServer`, `localServerCache`, `clearLocalServerCache` (stop → delete `<cacheDir>/torrserver/*` → start if it was running), `localIpv4` (Wi-Fi IPv4 or null); event `localServerState { running, error? }`. `supported` = file `libtorrserver.so` exists in `nativeLibraryDir`. On the first successful start, configure TorrServer via `/settings` (action `get`, then `set` with `UseDisk=true`, `TorrentsSavePath=<cacheDir>/torrserver`, `CacheSize=1073741824`), only if not done before (flag in plugin SharedPreferences). JS wrappers in `native.ts` in the existing style.

- [ ] Wrapper tests, implement, `npm run android:debug`, commit `feat(android): run TorrServer as a foreground service`

### Task 3: Phone — local server store, connect card, start screen, Settings

**Files:** `mobile/src/server/localServer.ts` (store), `mobile/src/screens/Connect.tsx`, new `mobile/src/screens/LocalServer.tsx` (route `localServer`), `mobile/src/screens/Settings.tsx`, `mobile/src/nav.ts`, `mobile/src/app.tsx` (autostart), `mobile/src/mobile.css`; tests `mobile/tests/localServer.test.tsx`, `connect.test.tsx`, `settings.test.tsx`.

Behaviour: exactly the spec «Что видит пользователь» 1–3 and mockups `Main.dc.html`, `Starting.dc.html`, `Settings.dc.html`. Store: `localServer` signal `{ supported, running, version?, ip?, error? }`, `refreshLocalServer()`, `startLocal()`, `stopLocal()`, autostart setting `tsp.localServer` `{ autostart: boolean }` (default true once the user started it the first time). Connect card shows only when `supported`, no saved servers and the network scan finished with no results (reuse whatever the Connect screen uses for scan). After a successful start: `addServer({ name: 'Этот телефон', url: 'http://127.0.0.1:8090' })`, set active, show address block, «Открыть каталог» → library. Settings section with switch, autostart, cache row (size via `localServerCache`, «Очистить»), the update note and the LAN warning «Сервер доступен всем устройствам в этой сети Wi‑Fi». Side effects injectable (deps seam) for tests.

- [ ] Tests, implement, full vitest, tsc, build:mobile, commit `feat(mobile): start TorrServer on the phone`

### Task 4: Phone IP for the TV and copied links

**Files:** `mobile/src/watch.ts` (`watchOnTvParams` caller path / server URL), stream-link copy path, tests `mobile/tests/watch.test.ts`.

Behaviour: spec «Запуск на ТВ». External player on the phone keeps `127.0.0.1`.

- [ ] Tests, implement, commit `feat(mobile): give the TV the phone address of the local server`

### Task 5: Automatic OMP release on new TorrServer

**Files:** `.github/workflows/torrserver-update.yml`, `.github/workflows/release.yml` (add `workflow_call` with input `tag`; checkout that tag), `scripts/torrserver-bump.mjs` (+ helpers in `scripts/torrserver-lib.mjs`), tests in `tests/scripts/torrserverLib.test.ts`.

Behaviour: spec «Автообновление сервера». The bump script: given the new tag, writes `torrserver.version`, bumps the patch version in `package.json`, `package-lock.json` (root entries), `webos/appinfo.json`, prepends `## x.y.z` + «- Встроенный TorrServer обновлён до <tag>» to CHANGELOG.md, prints the new version. Workflow: `schedule: cron '17 5 * * *'` + `workflow_dispatch`; job `check` (permissions `contents: write`) finds the latest release, exits when unchanged or when the arm64 asset/digest is missing, runs the bump, commits «chore: TorrServer <tag>» as github-actions[bot], pushes main, tags `v<version>`, pushes the tag; job `release` `needs: check`, `if` a release is needed, `uses: ./.github/workflows/release.yml` with the tag and `secrets: inherit`. Pure helpers tested (version bump, changelog insert, newer-tag detection).

- [ ] Tests, implement, `actionlint` if available (else careful YAML review), commit `ci: release OMP when TorrServer updates`
