### Task 1: Phone library view modes

**Files:** `mobile/src/screens/Library.tsx`, `mobile/src/mobile.css`, new `mobile/src/screens/library/*` if useful; tests `mobile/tests/library.test.tsx`.

Behaviour:
- Reuse `LibraryView`, `VIEW_OPTIONS`, `nextView`, `viewLabel` from `src/lib/libraryView.ts` and the shared setting `settings.libraryView` (`updateSettings`), exactly like the TV.
- A chip next to the sort chip cycles the view (icon + label, `aria-label` «Вид: <label>»); hidden on «История» (like sort).
- Modes on a 390 px phone:
  - `large` — today's 2-column posters with title and size (unchanged);
  - `small` — 3-column posters, title 2 lines max, no size line;
  - `list` — rows: 56×84 poster, title (2 lines), meta line (size · quality badge · season/episodes if known), chevron;
  - `compact` — text-only rows: title (1 line, ellipsis) + size on the right, 48 px row height.
- Equal title heights per mode (as on the TV: reserved lines). Quality badges keep working in poster modes.
- Tests: chip cycles all four modes and persists; each mode renders its distinctive structure (class per mode); hidden on «История».

### Task 2: Native — parallel ports and faster socket open

**Files:** `android/.../TvSocket.kt`, `OmpNativePlugin.kt`, `mobile/src/platform/native.ts`, `mobile/src/tv/tvStore.ts` (`port?: 3000 | 3001` on SavedTv), `mobile/src/tv/tvClient.ts`; tests `mobile/tests/native.test.ts`, `tvStore.test.ts`, `tvClient.test.ts`.

Behaviour:
- `tvConnect(ip, register, preferPort?)`: if `preferPort` is given, try that URL first alone for 2 s, then race the other; without it, start `ws://ip:3000` and `wss://ip:3001` in parallel and keep the first that opens (close the loser). OkHttp connect timeout 3 s. Resolve `{ port }` (the port that opened).
- tvClient passes the saved `port` and stores the winning port on the SavedTv (sanitizer accepts only 3000/3001).
- Tests: JS wrapper passes `preferPort` and returns port; tvClient saves the port and passes it next time.

- [ ] Implement, tests, `npm run android:debug`
- [ ] Commit `feat(android): connect to the TV on both ports at once`

### Task 3: Pre-connect, wake retries, pointer prefetch, queued presses

**Files:** `mobile/src/tv/tvClient.ts`, `mobile/src/screens/Remote.tsx`, `mobile/src/app.tsx`; tests `mobile/tests/tvClient.test.ts`, `remote.test.tsx`.

Behaviour:
- `warmUp(): Promise<void>` in tvClient: when an active TV exists and the state is not `connected`/`connecting`/`pairing`, connect; on failure retry every 1500 ms for up to 30 000 ms (stop on success, on pairing prompt, or when the active TV changes / app goes to background). Exposes `tvWaking` signal (true while retrying).
- Call `warmUp()` when the Remote screen mounts, when the app returns to the foreground (`appStateChange` isActive) and once at start when an active TV exists. Do not show errors for background warm-ups; Remote shows «Подключение…» while connecting/retrying.
- Right after a successful connect, open the pointer socket in the background (errors ignored; the existing lazy path still works).
- Remote button presses made while connecting are queued (in order, max 10, dropped after 15 s) and sent once connected — reuse the existing serialized queue in Remote.tsx/tvClient.
- Tests (fake timers + fake transport): retry cadence and stop conditions; pointer prefetch after connect; queued presses delivered in order after connect; no retry when idle without TV.

- [ ] Implement, tests, full vitest, tsc, build:mobile
- [ ] Commit `feat(mobile): connect to the TV early and retry while it wakes`

### Task 4: Turn the TV on (Wake-on-LAN)

**Files:** `OmpNativePlugin.kt` (+ small helper), `mobile/src/platform/native.ts` (`wakeOnLan(mac: string, ip: string): Promise<void>`), `mobile/src/tv/tvStore.ts` (`mac?: string`, sanitizer `^([0-9a-f]{2}:){5}[0-9a-f]{2}$` lower-case), `mobile/src/tv/tvClient.ts`, `mobile/src/screens/Remote.tsx`, `mobile/src/screens/Tv.tsx` (hint); tests.

Behaviour:
- After each successful connect, request `ssap://com.webos.service.connectionmanager/getinfo`; take `wiredInfo.macAddress` if the TV is wired (`wiredInfo.state === 'connected'` or IP matches), else `wifiInfo.macAddress`; normalise to lower-case colon form; save on the SavedTv. Errors ignored.
- Native `wakeOnLan`: magic packet (6×0xFF + 16×MAC) via UDP to `255.255.255.255:9`, to the /24 broadcast of the TV IP (`a.b.c.255`) on ports 9 and 7, sent 3 times 100 ms apart, on a background thread.
- Remote: the power button is «Выключить телевизор» when connected; when not connected and a MAC is known it is «Включить телевизор» (green): sends WoL, toast «Включаю <ТВ>…», then `warmUp()`; when no MAC is known, a toast: «Подключитесь к телевизору, когда он включён, — тогда его можно будет включать с телефона».
- Tv screen footnote adds: «Чтобы включать телевизор с телефона, на ТВ включите: Общие → Устройства → «Включение мобильного ТВ» (или «Включение через Wi‑Fi»).»
- Tests: MAC parse/normalise/sanitize; power button modes; WoL called with mac+ip then warmUp; native wrapper.
