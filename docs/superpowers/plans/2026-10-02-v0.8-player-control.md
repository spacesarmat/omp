# v0.8 «Управление плеером с телефона» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The phone controls OMP's player on the TV (pause, seek, episodes, tracks) through a «Сейчас играет» screen and a mini-player, and «Смотреть на ТВ» lets the user choose «Продолжить / Сначала».

**Architecture:** The phone runs a tiny HTTP server (Kotlin) and hands its URL to the TV in the launch param `report`. The TV posts its player state there every 500 ms and gets pending commands in the response. The phone checks the TV's OMP version through SSAP `listApps` before launching.

**Tech Stack:** TV: Preact + signals + TS (Chromium 53). Phone: Preact + Capacitor 8 + Kotlin plugin `OmpNative`. Vitest with jsdom.

**Spec:** `docs/superpowers/specs/2026-10-02-v0.8-player-control-design.md`

## Global Constraints

- TV code (`src/`) targets Chromium 53: no Error subclassing, no AbortController, no CSS grid / flex `gap` / `inset`, regex without the `u` flag and lookbehind. HTTP from the TV link uses `XMLHttpRequest` with `timeout = 3000`.
- Mobile code (`mobile/`) targets Android 8+ / WebView Chrome 90+.
- UI text Russian only. localStorage keys `tsp.*` via loadJson + sanitizer.
- App ids: Android `com.spacesarmat.omp`; TV `com.spacesarmat.torrplayer`.
- Vitest runs the REAL norigin spatial navigation; no global mocks / setup files.
- Protocol values (verbatim): launch param `report` = string starting with `http://`, length ≤ 200; message `{ v: 1, app: <APP_VERSION>, state: PlayerState | null }`; response `{ cmds: Cmd[] }`; post interval 500 ms; TV stops after 20 000 ms without a successful response; phone «Телевизор не отвечает» after 5 000 ms without a message, mini-player hidden after 30 000 ms; minimum TV version for control `0.8.0`.
- Commits: Conventional, subject only. NO Co-Authored-By / co-author / AI signature lines anywhere.
- No secrets in the repo.

## Shared types (TV `src/phone/protocol.ts`, imported by the phone via `../../src/phone/protocol`)

```ts
export interface TrackList { list: string[]; sel: number }
export interface SubList { list: { label: string; value: string }[]; sel: string }
export interface PlayerState {
  hash: string; file: number;
  title: string; subtitle: string; poster?: string;
  time: number; duration: number; paused: boolean; buffering: boolean;
  audio: TrackList; subs: SubList;
  next: { title: string } | null;
}
export interface PhoneMessage { v: 1; app: string; state: PlayerState | null }
export type Cmd =
  | { id: number; type: 'play' | 'pause' | 'next' | 'prev' }
  | { id: number; type: 'seek'; t: number }
  | { id: number; type: 'skip'; d: number }
  | { id: number; type: 'audio'; i: number }
  | { id: number; type: 'subs'; value: string };
export const POST_INTERVAL_MS = 500;
export const LINK_DROP_MS = 20000;
export const STALE_MS = 5000;
export const GONE_MS = 30000;
export const CONTROL_MIN_VERSION = '0.8.0';
/** Validates one command; null when malformed or unknown. */
export function sanitizeCmd(v: unknown): Cmd | null;
/** Validates a phone message (used by the phone); null when malformed. */
export function sanitizeMessage(v: unknown): PhoneMessage | null;
```

**Interfaces — Produces (`src/phone/link.ts`):**
```ts
export interface PlayerBridge { snapshot(): PlayerState | null; exec(cmd: Cmd): void }
/** The active player registers itself; returns unregister. Only one bridge at a time (last wins). */
export function setPlayerBridge(b: PlayerBridge): () => void;
/** Starts (or retargets) posting to the phone. */
export function attachPhone(url: string): void;
export function detachPhone(): void;
/** Posts now instead of waiting for the interval (after a command or a state jump). */
export function postSoon(): void;
export const phoneAttached: Signal<boolean>;
/** Test seam: replaces XHR transport; null restores. */
export function setLinkTransport(t: ((url: string, body: string) => Promise<string>) | null): void;
```

Behaviour:
- `LaunchPlan` gains `report?: string`; `parseLaunchParams` accepts `report` (string, `http://` prefix, ≤ 200 chars, trimmed) else `invalid`. A plan with only `report` is valid (not `null`).
- `runLaunchParams`: when `plan.report` is set call `attachPhone(plan.report)` before anything else; then continue as today (a plan with only `report` does nothing else: no navigation, no toast).
- Link loop: every `POST_INTERVAL_MS` posts `JSON.stringify({ v: 1, app: APP_VERSION, state: bridge ? bridge.snapshot() : null })` as `text/plain` to the url. Never two requests in flight (skip a tick while one is pending). On a response, parse JSON; for each `sanitizeCmd` result call `bridge.exec(cmd)` (dropped when no bridge), then `postSoon()` if any command ran. Any failure (network, timeout, bad JSON) counts toward the drop: after `LINK_DROP_MS` since the last successful response (or since attach) → `detachPhone()`. `attachPhone` with a new url replaces the old one and resets the timer. `postSoon` schedules an immediate post (coalesced).
- Default transport: `XMLHttpRequest` POST, header `Content-Type: text/plain`, `timeout = 3000`, resolves `responseText` on 2xx, rejects otherwise.
- Tests use fake timers and `setLinkTransport`.

After each exec call `postSoon()`.

### Task 3: Android — player server in the native plugin

**Files:**
- Create: `android/app/src/main/java/com/spacesarmat/omp/PlayerServer.kt`
- Modify: `OmpNativePlugin.kt`, `mobile/src/platform/native.ts`

**Interfaces — Produces (`OmpNativeApi` additions):**
```ts
/** Starts the server (idempotent) on the interface that reaches tvIp; resolves the report URL. */
startPlayerServer(tvIp: string): Promise<string>;
stopPlayerServer(): Promise<void>;
/** Commands the TV gets in its next response (in order, delivered once). */
queuePlayerCommands(cmds: object[]): Promise<void>;
/** Raw body of every TV message. */
onPlayerMessage(cb: (body: string) => void): () => void;
```

Behaviour (Kotlin):
- `ServerSocket(0)` bound to the local address chosen by opening a `DatagramSocket`, `connect(InetAddress.getByName(tvIp), 9)` and reading `localAddress` (no packets sent). URL `http://<ip>:<port>/omp/<token>`, token = 32 hex chars from `SecureRandom`. Calling start again with the same interface returns the same URL; with a different local address restarts.
- Accept loop on a background thread; each connection handled on a small executor (≤ 4). Minimal HTTP/1.1: request line, headers, `Content-Length` body up to 65 536 bytes (larger → 413). `POST /omp/<token>` → emit `playerMessage { body }`, respond `200` with `{"cmds":[...]}` (drain the queue), headers `Content-Type: application/json`, `Access-Control-Allow-Origin: *`, `Connection: close`. `OPTIONS` → 204 with CORS headers. Anything else → 404. Socket read timeout 5 s.
- `queuePlayerCommands({ json })` appends the array; queue capped at 50 (drop oldest).
- `stopPlayerServer` and plugin `handleOnDestroy` close the server.
- `native.ts`: wrappers with the same style as existing methods (`unavailable()` off-device; `onPlayerMessage` via `listen`).

- [ ] Wrapper tests, implement Kotlin + wrappers, `npm run android:debug` must build
- [ ] Commit `feat(android): local player server for TV state`
