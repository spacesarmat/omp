# v0.9.1 «Сеть и настройки сервера» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Fix phone-to-phone discovery of the embedded TorrServer (VPN, missing scan button) and let the phone edit TorrServer settings like the TV does.

**Spec:** user remarks 2026-10-02 (authority, quoted): a second phone «не видит сервер», screenshot shows VPN on and the address `10.1.30.36:8090`; «нужно сделать возможность редактировать настройки сервера который установлен на телефоне». Approved list (assistant message): 1) address strictly from Wi‑Fi, VPN warning; 2) «Найти в сети» always on the connect screen; 3) reachability check; 4) «Настройки сервера» on the phone like on the TV.

## Global Constraints

- Mobile Android 8+ / WebView Chrome 90+. TV code Chromium 53 (only the shared options module is touched there).
- UI text Russian only. Vitest: no global mocks/setup files, existing seams, run from repo root.
- Commits: Conventional, subject only. NO Co-Authored-By / co-author / AI lines.
- If `npm run android:debug` changes `android/*.gradle` only in line endings, restore them before committing.

Ruling (controller): item 3 «Проверить доступность из сети» is replaced by a hint — a request from the phone to its own Wi‑Fi address is routed internally by Android and proves nothing about other devices. Instead the connect screen shows a troubleshooting hint when a manual address or scan fails, and Settings shows the address plainly.

### Task 1: Wi‑Fi address and VPN warning

**Files:** `android/.../LocalTorrServer.kt` (`wifiIpv4`, new `vpnActive(ctx)`), `OmpNativePlugin.kt` (`localServerInfo` adds `vpn: boolean`), `mobile/src/platform/native.ts` (type), `mobile/src/server/localServer.ts`, `mobile/src/screens/Settings.tsx`, `mobile/src/screens/LocalServer.tsx`; tests.

Behaviour:
- `wifiIpv4`: only the Wi‑Fi network without VPN (keep current filter); the interface fallback accepts only `wlan*`/`swlan*`/`ap*` interfaces and never `tun*`, `ppp*`, `ipsec*`; prefer a 192.168.x / 172.16–31.x / 10.x address on `wlan0` when several.
- `vpnActive`: true when any network has `TRANSPORT_VPN`.
- When `vpn` is true, Settings (TorrServer section) and the start screen show the warning «Включён VPN — другие устройства могут не видеть сервер. Разрешите в VPN доступ к локальной сети или выключите его.» (warning style like the LAN warning).
- Tests for the JS side (warning shown/hidden).

- [ ] Implement, tests, `npm run android:debug`, commit `fix(android): Wi-Fi address only and VPN warning`

### Task 2: «Найти в сети» always

**Files:** `mobile/src/screens/Connect.tsx`, `mobile/src/mobile.css`; tests `mobile/tests/connect.test.tsx`.

Behaviour:
- A «Найти в сети» button is always on the connect screen (also with saved servers and on 32‑bit phones). It runs the existing scan (own /24; fallback subnets only without IP; cancellable) and lists found servers under «Найдено в сети»; a found server whose URL is already saved is marked «сохранён» and tapping it opens that saved server.
- The automatic scan on open keeps its current rules (no saved servers + supported) — the card logic is unchanged.
- When a scan finds nothing, or connecting to a manually entered address fails with a network error, show the hint: «Не находится? Проверьте, что оба устройства в одной сети Wi‑Fi, VPN выключен или разрешает локальную сеть, а в роутере выключена изоляция клиентов (гостевая сеть).»
- Tests: button visible with saved servers; results marked «сохранён»; hint after empty scan and after a failed manual connect.

- [ ] Implement, tests, commit `feat(mobile): find servers on the network from the connect screen`

### Task 3: «Настройки сервера» on the phone

**Files:** new `src/lib/serverSettingsOptions.ts` (move `MB`, `CACHE`, `PRELOAD`, `READAHEAD`, `CONNS`, `RATE`, `DISCONNECT`, `withCurrent` out of `src/screens/Settings.tsx`; the TV imports them — no TV behaviour change; Chromium 53 rules), `src/screens/Settings.tsx` (import), new `mobile/src/screens/ServerSettings.tsx` (route `serverSettings`), `mobile/src/nav.ts`, `mobile/src/screens/Settings.tsx` (entry row «Настройки сервера» under «Сервер», for the active server), `mobile/src/mobile.css`; tests `mobile/tests/serverSettings.test.tsx`, existing TV settings tests keep passing.

Behaviour:
- Screen title «Настройки сервера», subtitle = server name. Loads `c.getSettings()`; rows with the same labels and options as the TV: «Размер кэша», «Предзагрузка», «Опережающее чтение», «Лимит соединений», «Ограничение загрузки», «Ограничение отдачи», «Отключать неактивный торрент через», «Сохранять тайм-коды на сервере». Each row opens a bottom sheet with the options (radio list, current marked).
- Every change is saved immediately with `setSettings({ ...current, ...patch })`; toast «Сохранено»; on error toast with the error text and the row reverts.
- «Сбросить к стандартным» → confirm sheet → `resetSettings()` → reload.
- For the embedded server (active URL `http://127.0.0.1:8090`) extra rows: «Кэш на диске телефона» (on/off → `UseDisk`, keeps `TorrentsSavePath`) and «Размер кэша на диске» is the same `CacheSize` row (no duplicate).
- Loading/error states («Не удалось загрузить настройки сервера» + «Повторить»).
- Tests: renders values; change saves merged settings and toasts; error reverts; reset flow; local-only row visibility.
