# OMP 0.18.0-beta.4 («Новое» и подписки на ТВ через телефон, «Открыть в другом плеере») Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the TV gets a working «Новое» tab (findings and subscriptions kept by OMP on the phone, read and changed over the phone RPC), the «Следить за сериями» / «Следить за лучшим качеством» / «Хочу посмотреть» controls on the TV start working, and Android TV + phone get «Открыть в другом плеере» with the watch position coming back.

**Architecture:** monitoring stays on the phone (its WorkManager page owns `tsp.subs`, `tsp.monitorFound`). The phone RPC page (beta.3, `mobile/src/rpc/handler.ts`) gains monitor methods; the Kotlin route allow-list (`RpcRoute.METHODS`) gains their names; the TV calls them with `phoneRpc` from `src/phone/rpc.ts` through a typed wrapper `src/phone/monitor.ts`. The two watch flags live in TorrServer (`omp.w`, `omp.q` via `src/store/journal.ts`), so the TV writes them directly — no phone needed. «Хочу посмотреть» on the TV becomes a phone subscription (`better: true`) when the phone answers; the TV-local list stays as the fallback. External player: a new native plugin method starts an MX-Player-compatible `ACTION_VIEW` intent for result and resolves with the returned position.

**Tech Stack:** Preact + @preact/signals + norigin-spatial-navigation (TV, Chromium 53 on LG), Preact phone app (Capacitor Android), Kotlin (Android plugin, RPC route), vitest + jsdom, JUnit.

**Spec:** `docs/superpowers/specs/2026-10-06-v0.18-tv-design.md`, section «beta.4 — «Новое» и подписки через телефон». User additions (2026-10-06): «Открыть в другом плеере» on Android TV and the phone (system chooser, MX-compatible `return_result` → save the position; built-in player stays default; not on LG); no mockups — screens follow the existing TV screens (Обзор/Источники/Поиск style).

```ts
export type RpcFindingKind = 'episodes' | 'better' | 'sub';
export interface RpcFinding {
  subId: string; key: string; kind: RpcFindingKind; at: number; seen: boolean;
  result: RpcResult;                       // same allowed fields as search rows; key = finding key
  title: string;                           // subscription query, or the torrent title for episodes/better
  episodes?: { torrentHash: string; season: number; from?: number; to: number };
  better?: { torrentHash: string; have: string; got: string };
}
export interface RpcSub {
  id: string; query: string; quality: '' | '720' | '1080' | '2160';
  notify: boolean; better: boolean; unseen: number; checking: boolean; createdAt: number;
}
export interface RpcFeed { findings: RpcFinding[]; lastRun: number | null }
```

- Produces RPC methods (all params JSON, all replies small):
  - `feed {}` → `RpcFeed` (newest first, at most 100 = `FOUND_MAX`).
  - `subs {}` → `{ subs: RpcSub[] }`.
  - `subCheck {id}` → `{ started: true }` (starts `checkSubscription`; `subs` reports `checking: true` until done).
  - `subSet {id, notify?, better?}` → `{ sub: RpcSub }` (via `updateSubscription`).
  - `subRemove {id}` → `{ removed: true }` (via `removeSubscription`).
  - `wantAdd {query, better?}` → `{ sub: RpcSub, created: boolean }` (`addSubscription({query, quality:'', sources:null, notify:true, better: better !== false})`; if a subscription with the same normalised query exists, return it with `created:false`).
  - `findingLink {subId, key}` → `{ link: string } | { pending: true }` (resolve the finding's `SourceResult` with the same `resolveLink`/stash rules as `resolve`; phone-only `.torrent` → `RpcError('failed','sources.tvFileOnly')` exactly like `resolve`).
  - `findingsSeen {subId?, keys?}` → `{ ok: true }` (via `markFindingsSeen`).
- Consumes: `src/monitor/subs.ts` (`loadSubs`, `getSubscription`, `addSubscription`, `updateSubscription`, `removeSubscription`, `loadFound`, `markFindingsSeen`, `unseenCount`), `src/monitor/check.ts` (`checkSubscription`), `src/monitor/settings.ts` (`LAST_RUN_KEY`), the existing resolve helper used by the `resolve` method in `handler.ts`.
