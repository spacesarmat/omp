# v0.10 «OMP для Android TV» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** One APK runs OMP on phones and on Android TV; on TV it shows the LG-style TV UI with a native Media3 player, and the phone pairs with it by code and controls it like an LG TV.

**Spec:** `docs/superpowers/specs/2026-10-02-v0.10-android-tv-design.md` (binding; Russian copy verbatim). Mockups: scratchpad `omp-v010/project/*.dc.html` (paths given in dispatches).

## Global Constraints

- TV code (`src/`) still builds for webOS (Chromium 53 rules: no Error subclassing, no AbortController, no CSS grid / flex `gap` / `inset`, regex without `u`/lookbehind); Android-TV branches are gated by `platform.kind === 'androidtv'`.
- Mobile code Android 8+ / WebView Chrome 90+.
- UI text Russian only. localStorage keys `tsp.*` via loadJson + sanitizer.
- Ports/ids: control server port 8095, NSD type `_omp._tcp`, pairing code 4 digits valid 300 000 ms, token 32 hex, TV route `<localUrl>/tv/index.html`, back key → keyCode 461, media keys → 415/19/179/417/412/33/34/413.
- Vitest: no global mocks/setup files; existing seams; run from repo root.
- Commits: Conventional, subject only. NO Co-Authored-By / co-author / AI lines.
- If `npm run android:debug` changes `android/*.gradle` only in line endings, restore them before committing.

### Task 2: Android-TV platform layer in the TV app (keys, webOS-only features, updates)

**Files:** `android/.../MainActivity.kt` (in TV mode `dispatchKeyEvent`: BACK → JS `keydown`/`keyup` with keyCode 461 via `evaluateJavascript` dispatching a `KeyboardEvent`-compatible event the TV key handler understands; media keys mapped as in Global Constraints; root-screen back → `finish()` when JS reports it can't go back — use a JS callback `window.__ompBack()` returning boolean), TV code: `src/platform/launch.ts`, `hbchannel.ts`, `luna.ts`, `webosMedia.ts`, `src/api/discovery.ts`, `src/screens/Update.tsx`, `src/store/updates.ts` usage, Settings/Connect bits that call webOS-only APIs — gate them by `platformKind()`; on Android TV the Update screen offers one method: download and install the APK from `update-android.json` (`ANDROID_UPDATE_URL`, `native.downloadAndInstallApk` with progress) and hides HBC/root/PC methods; the update check uses the Android feed. Network discovery on Android TV uses the existing JS scan (`discover`) with the subnet from the plugin `localIpv4()` (luna `getStatus` is webOS-only). Tests for the gating and the Android update path.

- [ ] Implement, tests, full vitest, build, check:boot, build:mobile, commit `feat(tv): Android TV platform layer`

### Task 3: Native Media3 player

**Files:** `android/app/build.gradle` (media3 exoplayer, ui, datasource-okhttp or default http with headers), new `android/.../player/PlayerActivity.kt` (+ layout XML, styles), `OmpNativePlugin.kt` (`playNative`, `nativePlayerCommand`, events `nativePlayerState`, `nativePlayerClosed`), `mobile`-free JS: TV app `src/player/nativePlayer.ts` (wrapper over the plugin via `window.Capacitor.Plugins.OmpNative` — must not import Capacitor packages into the webOS build path; use a guarded global), `src/screens/Player.tsx` or a new `src/screens/NativePlayer.tsx` chosen by `platformKind()` in `src/app.tsx`; progress saving (same rules as `useProgressSync`: local every 5 s, server every 15 s and on close, `WATCHED_RATIO`), phone bridge (`setPlayerBridge` with snapshot from the latest state event and exec → `nativePlayerCommand`), «Продолжить просмотр?» stays in the TV UI before launching. Overlay per spec item 3 and mockup Player: bottom gradient, title, progress bar, time, buttons «Пауза»/«Воспроизвести», «Аудио: …», «Субтитры: …», «Следующая серия» (when there is a next item), hint line, «Управление с телефона» badge (shown after the first command), auto-hide after 4 s; DPAD left/right seek by `seekStep` (double press within 2 s: 10→30→30 like LG — reuse the rule), OK toggles pause, UP opens the tracks list (audio + subtitles incl. external files added as `SubtitleConfiguration`), BACK closes (returns state). Next item on end, with the LG «Следующая серия» banner behaviour simplified to auto-advance after 5 s countdown overlay. Tests: JS wrapper/bridge/progress logic with a fake plugin.

- [ ] Implement, tests, full vitest, build, build:mobile, android:debug, commit `feat(android): native Media3 player for Android TV`

### Task 4: Control server, NSD and pairing on the TV

**Files:** new `android/.../control/ControlServer.kt` (HTTP/1.1 on `ServerSocket(8095)` bound to all interfaces, small executor, body ≤ 64 KB, JSON in/out, CORS not needed), `OmpNativePlugin.kt` (start in TV mode on load; `pairingCode()` → `{ code, expiresAt }` new code each call; events `remoteLaunch { params }`, `remoteAttach { report }`, `remoteKey { name }`, `remoteText { text?|delete?|enter? }`), NSD registration (`NsdManager.registerService`, type `_omp._tcp`, port 8095, name = device name, TXT `v`), token store (SharedPreferences, up to 10 phones), volume via `AudioManager`, bring app to front on launch (`Intent` to MainActivity with `FLAG_ACTIVITY_REORDER_TO_FRONT`); TV app: `src/screens/PairPhone.tsx` (Android TV variant per spec item 4 + mockup PairTv: code block, «Новый код», «Готово»), `src/launchActions.ts`/`src/main.tsx` wiring of `remoteLaunch`/`remoteAttach` to `runLaunchParams`/`attachPhone`, `remoteKey` → synthesize key events (or route actions for CATALOG/NOWPLAYING), `remoteText` → focused input. Endpoints exactly as in the spec «Управление с телефона». Tests for JS wiring (events → actions) and the PairPhone variant.
