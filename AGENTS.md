# AGENTS.md: правила для ИИ-ассистентов в репозитории OMP

Ты работаешь над OMP (репозиторий spacesarmat/omp) для Andy. Пиши Andy по-русски, время указывай в МСК.
Цель: делать ровно то, что попросили, без лишних действий и лишних токенов.

## 1. Карта проекта
- `src/`: ТВ-интерфейс (Preact + Vite): LG webOS (`webos/` упаковка, `npm run tv:install` ставит на ТВ) и Android TV
  (тот же `src/`, сборка `vite.tv-android.config.ts` кладётся в APK как `tv/`).
- `mobile/`: телефонное приложение (Preact), `android/` проект Capacitor для телефона и Android TV
  (`npm run android:sync`, `npm run android:debug`). Встроенный плеер 2160 Player подключён сабмодулем `android/vendor/2160player` (репозиторий spacesarmat/2160player, общий с 2160 Ботя).
- `ops/billing/`: биллинг и админ-панель (`src/*.mjs` сервер и бот @OMPBILLINGBOT, `admin/` React-панель, Postgres).
- `ops/vps/`: сервер (NUC): `docker-compose.yml` + `docker-compose.nuc.yml`, `Caddyfile.nuc`, `deploy.sh`, `jacred/`, `jackett-monitor/`, `site/`.
- `scripts/`: релиз, CHANGELOG, Telegram-посты, TorrServer, проверки (`npm run check:boot`, `check:changelog`, `check:torrserver`,
  `node scripts/overflow-check.mjs`, `npm run screenshots`).
- Тесты: `npm test` (корень, затем billing через `ops/billing/vitest.config.ts`), `npm run build`, `npm run build:mobile`. Node 24.
- CI (`.github/workflows/ci.yml`): джобы `build`, `android`, `billing`. Релиз по тегу `v*` (`release.yml`), образ биллинга `billing-image.yml`,
  `torrserver-update.yml` (обновление TorrServer), `telegram-post.yml` (пост для уже выпущенного релиза), `vps-deploy.yml` (ручной деплой).
- `main` защищён: изменения только через PR.
- NUC: только с ПК Andy: `ssh -o BatchMode=yes andy@192.168.1.211`, каталог `/opt/omp-vps`,
  compose `-f docker-compose.yml -f docker-compose.nuc.yml`. Выкатка: `deploy.sh [--dry-run] <ref>`, откат `deploy.sh --rollback <dir>`.
- Сервисы: omp-billing, omp-postgres, omp-caddy, omp-jackett, omp-jacred, omp-flaresolverr, omp-torrserver, omp-warp, omp-warp-tunnel,
  omp-cloudflared, omp-cloudflared-home-nas, omp-docker-proxy (только чтение Docker API для мониторинга).

## 2. Жёсткие правила (нарушать нельзя)
Git и релизы:
- Ничего не вливать без явного "да" от Andy и зелёного CI (build, android, billing).
- Рискованные PR (Postgres, секреты, ключи, токены) проходят ревью Greptile. Докладывать только реальные замечания.
- Без трейлера `Co-authored-by: Cursor Agent`. Не делать force-push в открытый PR без согласия Andy.
- Один PR на одну задачу. CHANGELOG: правки в «Не выпущено», при релизе раздел переносится под версию.
- Технические изменения помечать `[tech]`, их видит только админ.
- Стабильный тег: релиз для всех + пост в Telegram (фото, заголовок, до 5 пунктов, inline-кнопки; без текстовых ссылок и файлов).
- Бета-тег: только бета-канал, без поста в Telegram. Релиз без прямой команды Andy не выпускать.
Текст:
- Только дефис "-". Длинное и среднее тире запрещены везде: чат, код, сайт, бот, релизы, CHANGELOG.
Секреты:
- Никогда не выводить и не вставлять в чат: `.env`, BILLING_TOKEN_SECRET, BILLING_PG_PASSWORD, строки подключения,
  токены Telegram-ботов, токены Cloudflare-туннелей, пароль Jackett, ключи JacRed, passphrase webOS, любые API-ключи.
- Не запускать `adminLoginLink.mjs` без просьбы. Вход в админку только через Telegram.
- Тестовую админ-панель можно прокликивать, но не менять её настройки.
Бот:
- @OMPBILLINGBOT единственный бот OMP. Он работает через getUpdates: не ставить webhook и не вызывать getUpdates его токеном откуда-то ещё.
  Мониторинг шлёт алерты только через sendMessage.
Сервер (NUC):
- Ничего не перезапускать и не пересоздавать без согласия Andy. `.env` и данные не трогать сверх согласованного.
- Перед изменениями делать бэкап (deploy.sh делает его сам). Любую правку на сервере зеркалить в `ops/vps`.
Устройства:
- Телефоны: только `adb install -r`. Никогда не удалять приложение и не чистить данные.
- S21 (R5CR102C5AA) принадлежит Andy. `com.spacesarmat.omp.test` не трогать.
- Перед тем как занять ТВ-приставку, предупредить 2160 Ботя.
UI для ТВ:
- Одинаково на 1080p и 4K, текст от 24px (исключение: только подписи тестового режима).
- Нельзя: flex `gap`, `aspect-ratio`, `inset`, `:has`.

## 3. Экономия токенов
- Сначала `rg` по имени или строке, потом точечное чтение нужного куска (offset/limit). Не читать файлы целиком "на всякий случай".
- Не выводить большие логи, lock-файлы, dist, сборки. Фильтровать: `rg`, `tail -n 50`, `--format`, `jq`.
- Не перечитывать то, что уже прочитано в этой сессии. Держать короткие заметки по ходу.
- Независимые команды запускать пачкой и параллельно. Зависимые склеивать через `&&`.
- Повторяемые шаги (ssh на NUC, проверки, деплой) брать из готовых скриптов, а не собирать каждый раз руками со сложными кавычками.
- CI ждать одним длинным ожиданием (`gh pr checks --watch` или один долгий poll), без частых опросов.
- Не повторять одну и ту же упавшую команду. Сначала понять причину (лимит API, нет сети у ПК Andy, права).
- Не делать работу сверх согласованного объёма. Идеи предлагать одной строкой в конце отчёта, а не выполнять.
- Спрашивать только когда ошибка дорогая (сервер, данные, релиз, устройства). В остальном выбирать разумный вариант и сказать, какой.

## 4. Порядок работы
1. Понять: что именно просят и где граница задачи. Если это сервер, релиз или устройство, свериться с разделом 2.
2. Найти: `rg` по коду, `git log -S`, нужный workflow или скрипт.
3. План в 3 строки: что меняю, как проверю, что может сломаться.
4. Изменить минимально, в стиле соседнего кода. CHANGELOG в «Не выпущено», если изменение видно пользователю.
5. Проверить локально: `npm test`, `npm run build`, для мобильного `npm run build:mobile`, для ТВ-UI скриншоты 1080p и 4K.
6. PR в ветке `feat/...`, понятное описание, скриншоты для UI. Для рискованных PR запросить Greptile.
7. Дождаться CI (одно ожидание). Красное: починить причину, а не перезапускать вслепую.
8. Доложить и ждать "да" на влив. После влива деплой только по согласованию, с бэкапом и проверкой здоровья.

## 5. Формат отчёта Andy
- Первая строка: результат (сделано / не сделано / что мешает).
- Дальше 3-5 коротких пунктов: ссылка на PR, CI, что проверено, что осталось, что нужно от Andy.
- Без секретов, без длинных логов, без тире кроме "-". Время в МСК.
